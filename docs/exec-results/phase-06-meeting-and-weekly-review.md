# Phase 06 Executive Result — Meeting and Weekly Review

> 状态：第一轮主要实现已完成。推广讲义日度事实从 2026-07-01 开始；下一步使用部分真实非推广 T+7 / T+15 样本验证周会流程，不把一次性补完所有历史待办作为收尾前置条件。

## 一、已交付闭环

- 日度推广复盘独立保存推广原始事实；周度区间汇总统一进入例会总复盘。
- 非推广帖按实发日严格使用 T+7 → T+15 节点，会议只引用已完成结果，不重复填写原始指标。
- 周度业务复盘支持自选日期区间、跨月标题、区间重叠/断档提示、本周总览和排期对齐。
- 计划对齐以排期管理为基线，区分已发、延期、未发和区间外计划的额外实发。
- 推广区间复盘提供表格与 Block 双视图，共用同一草稿；聚合消耗、实际开口/留资与成本，并人工填写区间点击率、当前情况和正在执行的动作。
- Block Inspector 按 Daily Metric 展示测试/放量日期、自动指标和逐日事实；区间内仍只录入一个整体点击率。
- 本周到期和历史遗留的非推广节点自动进入会议候选项，未完成项保留原始复盘入口。
- 待验证/待解决事项按待处理、验证中、已解决和暂缓管理，未解决项自动跨周结转，每次会议追加进展。
- 会议草稿可保存，首次定稿为 V0，后续更正生成 V1+；已定稿快照不被业务数据的后续变化静默改写。
- 例会总览支持单条删除草稿和勾选多份草稿后批量删除；客户端预览数量并二次确认，服务端只允许删除 `draft`，已定稿 V0 / V1+ 被硬性拒绝。

## 二、数据与兼容

- 旧 `operations_stage_review_meeting` 迁移为 `operations_review_meeting`，保留已有会议 ID。
- `operations_review_meeting_version` 保存不可变会议版本快照。
- `operations_review_action_item` 和 `operations_review_action_progress` 分别保存稳定问题与逐会议进展。
- 旧 `/api/stage-reviews` 仅保留兼容转发；新页面统一使用 `/api/meeting-reviews`。

## 四、收尾与下一步

1. 以 2026-07-01 为推广讲义日度数据起点，先选择一个真实周期创建周度业务复盘。
2. 非推广数据先录入一组有代表性的真实样本：至少包含一条 T+7、一条 T+15、一条本周到期和一条历史遗留。先验证录入、引用和会议展示是否清楚，再按到期日顺序分批清理其余队列。
3. 历史待复盘不要为了“全部填完”而编造指标或低质量结论；无法取得可靠数据的节点暂保留待办，后续再确认是否需要“无数据关闭”机制。
