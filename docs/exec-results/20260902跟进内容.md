## 一、当前任务总结

1. 非推广复盘保留“待复盘 / 已录历史”两个视角，主体统一为高密度表格，一行对应“帖子 × 复盘节点”。表格展示实发日期、笔记 ID、帖子、分类、节点、点击率和 3 秒阅读率；指标下方继续使用包含当前帖的实时同类均值。
2. 复盘表格不显示差值，不按指标高低标红或标绿；仅用中性状态区分待填、逾期和已完成。帖子名称仍直接链接项目文档，缺失时显示“项目文档待补”。
3. 点击或使用键盘打开复盘行的右侧 Inspector；待复盘可填写数据截至、两项指标和可选结论，历史行可查看并编辑现有记录。移动端 Inspector 使用全屏布局。
4. 小红书笔记 ID 统一保存在 `operations_content.platform_note_id`，去除首尾空格、转小写并校验为 24 位十六进制值，数据库保证全局唯一。同一逻辑帖子的 V0/V1、多条排期、多个 Campaign 和全部复盘页面统一读取该值，不在下游表复制。
5. 笔记 ID 不在实发登记时填写。推广帖可以先开始测试，首次保存日度复盘时与日度事实原子补齐；非推广帖在首次保存任一复盘节点时原子补齐。已有 ID 默认只读，统一更正入口必须确认全版本和复盘同步影响。
6. 排期工作流已拆分为“新做帖 / 创建改帖”、“编辑排期”和“实发登记”。前两个阶段允许项目文档暂缺；帖子实际发布后，实发登记必须同时填写实发日期和 HTTP/HTTPS 项目文档链接。
7. 排期 Inspector 将“实发登记”作为唯一主操作，编辑排期和创建改帖为次级操作；“删除排期”已从表格操作列移至 Inspector 底部，使用弱化危险样式，避免小频率操作占据过大视觉重心。
8. Excel 中的历史笔记 ID 已通过受控预检完成 development 回填：32 个已有推广或非推广复盘事实的帖子全部匹配，未覆盖为 0。三篇同名 `STEP喜报` 已按现有点击率和 3 秒阅读率一一对应；回填后再次验证通过，一次性脚本已移除。
