## 五、下一步实施 Prompt：非推广复盘表格与笔记 ID

> 以下内容是下一个开发任务的完整执行要求。

### 目标

将非推广复盘改为高密度表格，并为推广和非推广帖子更新统一的小红书笔记 ID。本次不重做推广页布局，只补充高优先级的笔记 ID 展示与首次录入能力。

### 非推广复盘表格

1. 保留“待复盘 / 已录历史”两个视角，主体统一改为表格，一行对应“帖子 × 复盘节点”。
2. 固定字段为：实发日期、笔记 ID、帖子、分类、节点、点击率、3 秒阅读率。
3. 帖子名称继续直接链接项目文档；缺少链接时显示“项目文档待补”，不增加独立文档列。
4. 点击率和 3 秒阅读率单元格下方显示“同类均值 xx% · n 篇”，沿用同学科、同分类、同节点且包含当前帖的实时口径。
5. 当前不显示差值，不根据指标结果标红或标绿；只使用中性节点状态区分待填、逾期和已完成。
6. 笔记 ID 列使用弱化的等宽小字和中间省略，完整值可悬停查看及复制；在详情编辑区显示完整值，不让它抢过帖子名称和指标。
7. 点击或键盘打开表格行的右侧 Inspector：待复盘填写数据截至、两项指标和可选结论；历史行查看并编辑现有记录。移动端 Inspector 使用全屏。

### 笔记 ID 模型与业务规则

1. 在帖子主体 `operations_content` 增加可空、唯一的 `platform_note_id`，不复制到排期、Campaign、日度事实或复盘快照；同一帖子的全部版本和页面统一读取该值。
2. ID 去除首尾空格并转小写，按当前 Excel 中的 24 位十六进制小红书 ID 校验；重复 ID 返回明确冲突。
3. 笔记 ID 不在“实发”时必填；非推广首次保存任一复盘节点时，若帖子没有 ID，则必须在同一事务中填写并保存。
4. 推广帖点击“开始测试”时要求填写缺失 ID；历史遗留 Campaign 若仍缺 ID，则在下一次日度复盘保存前补填。
5. 已有 ID 默认只读沿用。使用统一的“更正笔记 ID”入口时，先显示旧值、新值和“该帖子全部版本与复盘都会同步”的确认提示；服务端收到确认标记后才允许更新。
6. 推广页不改变现有待办、生命周期和历史结构，只在帖子身份区高优先级展示完整笔记 ID，并增加首次录入与更正能力。

### Excel 回填与安全边界

1. 使用临时受控脚本读取 `public/excel` 中两份 Excel，从推广日/周/月复盘、“关联复盘”和“非推广单篇粒度复盘”提取笔记 ID。
2. 默认只读预检，按帖子名称、实发日期、复盘指标、Campaign 日期和版本链建立映射。三篇同名 `STEP喜报`按现有点击率和 3 秒阅读率一一对应。
3. 任何冲突、多义映射或重复 ID 都阻止写入，不仅按标题猜测。预检通过后才可以在明确的 development 数据库事务中回填。
4. 回填后验证所有已有推广或非推广复盘事实的帖子都已有 ID，并核对同一帖子的 V0/V1、多条排期和多个 Campaign 共享同一 ID。完成后移除一次性脚本。
