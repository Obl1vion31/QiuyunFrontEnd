# 销售工作台与企业微信客服

## 先验收客户扫码收发

首个验证对象是从专用链接或二维码进入的企业微信客服会话。企业微信后台通常将这项能力标为「微信客服」。企业内部的「智能机器人」可以另行测试员工与机器人的对话，客户侧验收以客服号为准。

| 顺序 | 操作 | 确认结果 |
| --- | --- | --- |
| 1 | 企业管理员打开企微管理后台的「微信客服」，创建或选定一个仅用于联调的客服号，设置可用的测试接待人员。 | 拿到独立客服号的私用入口。测试者可以从手机微信进入客服会话。 |
| 2 | 创建测试自建应用，将该应用加入「可调用接口的应用」，按后台设置选定由 API 管理的测试客服号和相应可见范围。 | 应用能操作所选客服号。对既有正式账号保持原接待设置。 |
| 3 | 在相应的接收消息或事件配置中填入测试服务的 HTTPS 回调 URL、Token 和 EncodingAESKey。如果后台要求选择事件，启用客服消息及事件。按后台实际提示完成域名校验与企业可信 IP 配置。 | 保存回调成功。企微发来的 GET 验证请求通过验签和解密，服务返回原始明文。 |
| 4 | 测试者在专用客服会话发送指定测试文本。服务验证回调事件，用 测试自建应用的凭据获取访问令牌，按客服号调用 kf/sync_msg 拉取正文，再调用 kf/send_msg 固定回复「你好」。 | 手机实际收到「你好」，服务侧能核对收事件、拉正文和提交回复。重复回调只产生一条应答。 |

固定回复由收到的测试消息触发。真正的验收要同时看到用户发出的测试文本、后台拉取到这条消息、调用发送接口返回成功，以及微信客户端显示回复。系统欢迎语和发送接口的成功返回分别只说明入口可用和发送请求被接收。按游标拉取消息，且按消息 ID 去重。仅在测试账号以及客服接口允许的会话状态和发送窗口内回复。

CorpID、测试客服号标识用于定位。应用 Secret、回调 Token 和 EncodingAESKey 保存在联调服务端的私有环境。当前公网域名能否作为回调，以及出站能否满足可信 IP，以企业后台的实际校验为准。现有销售页面使用项目登录，企微回调由服务端按平台签名校验。两处通过服务端对接。

回调和出站 API 均实测后，用同一个回复入口把固定文本换成自有模型 API 并保留原测试用例。课程查询和人工接手随后按本页流程接入。

## 工作台的目标流程

两个入口共用接待逻辑。新客由企微客服号收消息。已加顾问企微好友的客户由销售选取有授权的对话，或在符合开通和授权条件时读取会话存档。两者统一整理上下文、查课程资料、起草回复，再按各自的会话权限确定发送方式。好友会话首版由员工回企微发送。正式销售来源核对继续按已确认流程操作，月度运营「私域来源与成本」仍在原入口手填。

- **课程库**由有权限的销售或运营维护。课程、班型、价格、班期、名额、适用对象和政策要明确当前有效版本。后端向模型提供本轮命中的资料。客户问到资料缺失的字段时，模型说明待确认，并给出可执行的下一步。
- **会话和待接手**让顾问看到客户需求、已查资料、建议稿及接手原因。首版统一由顾问审稿发送，再在权限通过实测的客服会话试开低风险自动回复。AI 优先回答与追问。退款、投诉、明确要求人工和需顾问决定的事项由人工处理。顾问可主动接手，接手后暂停该会话的自动回复。
- **工具池**首批提供「查课程」和「请求顾问接手」。查课从服务端读当前资料。请求接手由后端生成一个待办，向负责人发企微应用提醒，顾问点开核对上下文并接话。
- **对话质检**支持按单轮或整段评分、改稿和记录原因。保留 AI 原稿、实际发送稿和顾问意见。客户可选「有帮助／没解决」。课程库、接手待办和质检记录由服务端按账户权限共享。

## 评测与回流

从有相应授权的对话提取咨询内容、来源帖、成交用时和可复用话术，区分客户明确反馈和顾问判断。纳入成交、未成交、待定和转人工案例，由模型初标、顾问复核。按客户切分训练、验证和测试集后再拆为片段，训练输入只带当轮可见的内容。

先固定一个 API 底座、Prompt 和课程查询做基线，同时准备训练样本和独立评测。基线和候选版共用同题盲测及多轮对练，分别记录资料是否查中、回复是否用对。首轮评分建议为课程事实与依据 30、意图识别 15、追问与下一步 20、话术与语气 20、人工边界 15。编造课程或报价、越权承诺、漏掉必要交接或顾问接手后仍自动发消息，判当前用例失败。

事实和检索问题先修资料或查询，流程问题先更新 Prompt 或接待规则。给对资料后仍反复出现的话术、承接或追问偏差，复核「当轮上下文＋顾问认可回复」，以 JSONL 训练 LoRA SFT 候选。在同底座、同资料和同 Prompt 上与基线比较。将复核后的好例留档、难例补入评测，训练候选通过复测后再扩大自动回复范围。
