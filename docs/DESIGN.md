# 设计方向

## 总体原则

- 首页是全站唯一允许大胆视觉表达的页面。
- 首页后半段和未来业务页面保持简洁、低动效和高可读性。
- 视觉必须服务真实前端工作：内容策划、阅读体验、视觉设计、发布、用户触点和复盘。
- 不用普通卡片网格、装饰性编号或无业务含义的渐变制造“设计感”。
- 中文阅读体验、移动端可用性、键盘焦点和减少动态效果模式属于质量底线。

### 工作台的一致性基准

- 先确定语义：业务信息、状态、筛选、展示方式、选项与动作按阅读和操作关系分组，再安排视觉结构。统一空间尺度与组件规则，允许日历、矩阵、表格和表单按功能采用不同结构与密度。
- 全局同步、局部例外：公共模式优化前查找整个工作台的全部消费者，同步适用组件、页面、规则与验收；用户明确限定局部时遵从限制。不扩大到无关业务，不机械复制旧例外。

- 整个工作台共用一套产品界面。结构、视觉、组件、信息层级、交互反馈与不同状态均以共享实现为基准；已有页面中的例外须核对后再复用，不因存在而自动成为规范。
- 局部操作，局部变化。筛选、排序、分组、视图切换及展开收起只调整功能必需的内容，保留公共位置、尺寸、节点及阅读连续性；内容组织变化不能连带更换整张表格或插入说明区域。
- 同类数据与操作目的先统一输入模式和行为，再统一外观；日期时间、单选、多选、搜索、筛选与切换都按此判断。导航到不同数据视图与原位调整展示方式允许采用符合其语义的不同控件，不能只因外形相近而机械合并。
- 工作台中文使用 `system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`。正文基准 13px／20px，辅助信息 12px／18px，行标题与主指标 14px／20px；同类内容使用同一层级。顶栏、导航和页面标题沿用对应共享组件的层级，不将所有文字改成同一字号。
- 工作台字体基准由 `business-typography.css` 与语义组件共同维护，覆盖原生控件及正文外弹层。页面／详情标题为 18px，区块标题 14–16px，正文与常规控件 13px，辅助信息 12px；紧凑导航保留适合窄屏的规格。标题、按钮和重点值通常使用 600 字重，普通输入与正文使用 400–500；核心统计 20–24px，数字使用 tabular-nums，不用等宽或衬线字体制造强调。
- Inspector 底部动作复用共享操作区：主要动作蓝底，次要动作中性白底，40px 控件、13px／600 文字、8px 间距。灰色外观不等于禁用，实际状态以 disabled／aria-disabled 和可执行业务条件判断。
- 日期和普通中文使用正文字体；数字对齐优先使用 `tabular-nums`，代码或原始 ID 才按需要使用等宽字体。空态、版本历史、弹层及异步加载的内容同样适用，不能依赖浏览器默认按钮字体。
- 业务文案不展示开发思路或实现过程，不重复按钮、筛选和表头已经表达的信息；说明是可选的，仅保留理解和正确操作所必需的业务信息。加载、保存、错误反馈与必要的影响确认继续保留。
- 日期操作直接写明确的目标业务日，避免“某日之后”再补一段生效日期。密集行内的日期标签、选项与保存按同一阅读顺序就近排列，桌面同行对齐，窄屏按完整字段组换行。短状态不拆字；同一状态或日期不通过多个说明段重复表达，详细记录按需展开。
- 控件、颜色、边框、圆角和阴影复用现有共享基准，不因新增功能另建一套；确需突破规范时先说明功能理由并获得用户确认。交付前检查跨页协调、组件及反馈一致、布局跳动、冗余内容和修改范围。

### 控件、筛选与表单抽屉

- 常规表单显式接入 `business-form`、筛选接入 `business-filter`，共享 `src/styles/business-forms.css`；密集行内指标与月份矩阵保留适合其内容的规格，不用全局元素重置强行套用表单结构。
- 完整时间统一通过 `businessDateTime` 显示为上海时区 `YYYY-MM-DD HH:mm`，仅日期通过 `businessDate` 显示 `YYYY-MM-DD`；SSR、异步详情、历史和回显均复用。月历格内有明确日期上下文时可显示时分短格式。完整日期时间统一复用 `BusinessDateTimeFields` 的独立原生日期与时间选择，日期在左、时间在右；仅日期仍使用日期控件。原字段通过共享控制器拼合提交，名称、必填、默认值、只读／禁用及既有服务端时间解析沿用各业务，不使用 `datetime-local` 或普通文本替代同类时间输入。
- 可编辑控件使用白底实线；只读／禁用控件使用浅底与虚线，系统状态用文字或状态标识，不伪装为可编辑字段。必填与错误沿用实际字段校验，空反馈不占位。
- 居中编辑和轻量任务使用 `BusinessFormDialog`，按内容选择宽度；共享头部、滚动正文和固定操作区，与 Sheet 共用表单规范，保留各自出现位置和现有标题栏配色。
- 表单控件与按钮常规高度 40px，筛选与展示方式使用 36px 紧凑规格；同一区域按同一基线、尺寸和间距排列。必填标识与字段标签同行，标签与控件间距 6px，相关字段分列时等宽，字段组间距 16px；字号与颜色使用共享变量，不依赖浏览器默认字体。
- 筛选条件组成一组，展示方式组成独立操作组。两个互斥展示模式使用 `BusinessViewSwitch` 原生单选分段控件，保留键盘、焦点和 URL 状态，不将其伪装成业务属性复选框。现有顶栏继续复用专用 Toolbar 控件，不通过单页覆盖改变其几何。
- 编辑类表单抽屉使用 `BusinessFormSheet`：桌面宽度 680px，900px 及以下占满屏幕，头部与底部固定、只有内容区滚动，底部计入安全区。保持已有深蓝色标题栏配色，标题、版本和关闭操作各自承担实际信息；业务内容通过插槽接入，数据、权限与未保存保护由原业务适配器处理。
- 编辑排期按内容名称整行、学科／分类并排、日期／时间并排、推广与朋友圈同组选项、项目文档整行排列。发布登记沿用相同标签、输入、日期、选项与按钮规格；具体字段不同不改变容器规范。空校验信息不占位，必要权限、错误与影响说明保留。
- 表格与容器按真实内容自然增高，不为少量数据撑出整屏空白；窄屏滚动局限在表格内部。重复 ID 等低优先级信息可移到悬停和详情，版本及轮次须清晰保留；主指标与差值并列、同类均值及样本量另行显示，避免重复轮次标签。

### 异步交互与加载反馈

- 区分读取、后台刷新、导航与写入。来源卡片在详情读取中保持原文、状态色、尺寸与可用性，不以最近点击元素推断加载按钮。读取先显示已知摘要，500ms 内不显示加载文案或动画；超过时只在目标 Inspector 中显示一处加载状态，关闭操作始终可用。
- 目标容器负责读取反馈，壳层保留写入与会话错误兜底；导航使用现有进度。保存、删除等写入保留防重复及动作反馈，不叠加同一读取任务的全局动画。请求完成、失败、关闭和切换时均清理状态，旧响应不得覆盖当前对象。
- Inspector、侧边 Sheet 共用 220ms 进出节奏；Sheet 沿右侧路径进入与退出，退出完成后才执行原生关闭。居中 Dialog 保持居中并成对淡入淡出；遵守减少动态效果。
- 站内未保存确认使用 `businessConfirm`，默认聚焦“继续编辑”，“放弃修改”明确执行丢弃；取消保留表单、焦点与滚动。重复触发不叠加对话框；浏览器刷新和关闭页签仍由原生 beforeunload 保护。
- 删除、恢复、定稿、历史影响与共享身份更正同样使用 `businessConfirm`，明确对象、影响和确认动作，默认聚焦取消；站内不再调用浏览器 confirm／alert。失败在所属表单、记录或操作区反馈，保留输入并允许重试。

## 业务页面：高密度运营台账

- 业务页使用低动效、清晰分区和高信息密度，不复制首页的 3D 穿越效果。
- 业务页吸收 Apple Design 的界面原则而不是仿制 macOS：桌面端以垂直导航和上下文工具栏组织层级，移动端自适应为紧凑 Bar；按下即反馈，弹层从触发关系中产生并沿原路径关闭。
- 同属“内容发布控制台”的页面必须共享同一应用壳层，不得分别复制并修改 Sidebar、Toolbar 和移动端导航 CSS。新增业务页面应复用统一 Layout / 组件；已有页面出现差异时优先收敛公共壳层，不在单页继续打补丁。
- 半透明材质只用于浮动工具栏、弹层等功能性上层，表格和密集数据区保持实色与清晰对比；不以毛玻璃代替信息层级。
- 帖子版本是业务结构，不是装饰编号：V0 表示新做帖，V1 及以后表示从原版本派生的改帖。
- 排期页采用 `Sidebar + Toolbar + Inspector + Sheet` 的工作台结构；桌面端左侧导航保持稳定，主区默认承载月历，并可切换紧凑时间轴台账；选中内容后在右侧检查详情和版本关系。
- 排期与推广状态共用同一份按日分组的紧凑时间轴数据，不建设相互割裂的推广看板；状态带提供本月内容、待发布、推广中、测试中、放量中、尚未登记和已发布视角，其中“推广中”明确拆分测试与放量数量。
- 台账与月历是同一批数据的两种表达；新增、编辑和改帖统一使用右侧 Sheet，移动端使用全屏形式。
- 台账不设置独立删除列；删除排期移入 Inspector 底部“更多操作”，使用弱化危险文字并在执行前明确提示不可恢复。Inspector 以实发登记为唯一主动作，编辑排期和创建改帖作为同一层级的次级动作。
- “推广周期已结束”“测试淘汰”和“放量淘汰”使用不同文字标签，三者均不进入当前推广状态带。
- 月份标记、表头、状态标签和日期用于编码真实业务信息，不作为装饰编号。
- 延期发布、尚未登记、数据库异常和字段错误必须有明确文字。紧凑月历通过图例、悬停提示、可访问名称和详情保留状态文字，卡片底部不重复展示。
- 表单保留可见标签、键盘焦点和字段级错误；横向信息表格在窄屏可滚动，不压缩到不可读。
- 学科与帖子分类使用相邻的两级选择控件；帖子分类只显示当前学科下的有效选项，切换学科时清除不再匹配的分类。
- 各学科新建或编辑必须选择有效分类，可使用“临时帖”；无法确定学科时使用“临时学科 / 临时帖”，历史空分类归入临时帖。
- 创建改帖只保留“具体改动说明”，输入框下方以简短说明示例提示“改动了哪些部分”以及“改动原因和希望达到的效果”，不增加额外装饰。
- 完成情况在独立实发登记 Sheet 中作为系统计算结果展示，不提供手动状态选项；满应发 2 小时未登记先提醒“尚未登记”，登记后按真实发布时间核对逐日原因；实发登记补齐每一天的责任方与必填文字。历史理由默认折叠，展开查看逐日明细。新做帖、改帖和编辑排期不混入实发字段。
- Inspector 和 Sheet 必须管理初始焦点、Esc 关闭与未保存提醒；移动端 Inspector 和 Sheet 使用全屏形式，控制台已实现入口收纳为底部 Bar。
- 沿用 `Control Night`、`Blueprint`、`Marker Orange` 和 `Monitor Mint`，但把大胆表达留给首页。

### 内容发布控制台统一壳层

年度总周期规划、排期管理、推广帖复盘、非推广复盘、例会总复盘和系统设置属于同一个应用。所有页面使用同一个共享 Sidebar 组件；跨页面切换时，只有主内容和当前导航状态可以变化，外围框架不得跳动或换色。

- 桌面 Sidebar 固定使用同一宽度、背景色、内边距、品牌区高度、导航行高度、圆角、图标尺寸、激活态和底部区域。具体尺寸与色值以当前统一壳层实现为准，可以根据跨页体验继续调整；不得因模块主题单独换色或改变主内容起点。
- 顶部 Toolbar 固定使用同一高度、左右内边距、底色、边框和三列对齐基线。具体高度由跨页面实际信息密度共同确定，可以继续试调；中间筛选或切换控件不得单独把整条 Toolbar 撑高。
- 当前 Toolbar 桌面端固定为 `72px`、移动端固定为 `62px`，横向占满 Sidebar 右侧 Workspace；标题、年月导航、分段切换、汇总和操作按钮均使用共享组件，单页不得覆盖其字体、颜色或几何。
- Toolbar 左侧信息统一为“模块主标题 + 当前上下文”两行结构。主标题的字号、字重、行高一致；第二行只承载年份、月份、视角或截止日期等上下文。`THE PLAN`、`Daily Promotion Review` 等英文可以作为辅助名称，但不能改变标题区高度和基线。
- Toolbar 中部用于当前页面的日期导航、视角切换或阶段切换，右侧用于汇总和主要动作。某页没有对应内容时保留网格对齐，不用改变整体高度补偿。
- Toolbar 中部只允许单行控件。推广每日、阶段和历史共用同一个顶栏节点及固定的“每日复盘 / 阶段复盘”切换；历史属于每日内部视图。数据截止时间放在生命周期标题旁，不因切换改变公共控件位置。
- 移动端统一使用同一底部导航高度、背景、图标和安全区规则；Toolbar 的移动端高度、标题折叠方式和主要操作位置也必须一致。
- 页面专项色只进入内容区的数据编码，例如学科色、测试黄和放量绿；不得改变 Sidebar 或 Toolbar 的基础色。
- Sidebar 必须形成完整的样式隔离边界：组件根节点及全部后代统一声明 `box-sizing: border-box`，并由组件显式声明字体族、基础字号和行高。不得让 Sidebar 继承页面级 `* { box-sizing }`、`body` 字体或 `body` 行高；否则 scoped 与 global 页面会把同一导航行计算成不同高度。
- 业务页面只能引用共享 Sidebar 并传入当前激活项，不得声明 `.sidebar`、`.module-nav`、`.sidebar-foot` 等独立侧栏结构或样式。修改 Sidebar 只进入共享组件；右侧 Workspace 的样式不得命中共享侧栏命名空间。
- Sidebar 以“计划与执行 / 复盘与沉淀”表达真实业务分组，导航使用单行中文名称和语义线性图标。当前项保持完整圆角选择面；hover、键盘焦点、按压和加载必须各自可辨，但不得通过图标弹跳、整页淡入或分散动效制造反馈。
- 跨页面切换时 Sidebar 持续存在，点击先更新当前项；只有等待超过短暂阈值才在 Toolbar 下缘显示单一加载条。预取只由 hover、键盘 focus 或触摸按下触发单个目标，不在页面打开时请求全部模块。
- 验收业务页时必须连续点击所有控制台模块，检查 Sidebar、Toolbar、主内容左边界和首屏垂直起点是否逐页保持不动。单独截图看似合理但跨页跳动，仍视为不合格。

壳层参数属于实现细节，不作为永久设计结论；长期结论是同一控制台的所有页面必须使用相同参数和信息结构。发现跨页差异时应通过共享壳层一次性消除，不把某次试调值继续复制到新页面。

控制台页面结构统一由 `BusinessConsoleFrame`、`BusinessConsoleToolbar`、`BusinessPageHeader` 和 `BusinessSectionHeader` 组合。页面级标题使用清晰的中文工作对象，不增加装饰性英文眉题；说明和右侧元信息仅在确有必要时提供，省略时不生成占位或空行。紧凑台账页可以直接从工具栏进入内容，不强制增加页面级标题。

- 页面标题只说明当前工作对象与必要边界，不重复操作顺序、到期规则或显而易见的步骤。
- 区块标题使用共享 Section Header；标题、说明和右侧计数的字号与间距不得由单页重新定义。
- 相同层级的 Bar 使用共享 Toolbar；页面只通过命名插槽提供日期导航、视角切换、汇总和主要动作。
- 新业务页面优先组合上述组件。只有信息结构确实不同且无法通过组件 Props 或插槽表达时，才新增视觉结构。

### Daily Promotion Review

- 节假日暂停位于“待完成复盘”标题栏最右侧，与标题和历史入口在同一行：暂停至日期、一键暂停；生效后原位提供调整截止日和提前恢复。窄屏在同一标题栏内换行，不出现独立卡片或规则推理文案。员工与管理员操作一致。
- 推广日历只表达推广帖，不混入非推广内容；每篇帖子使用一张独立的全宽生命周期卡片，阶段宽度按截止日内的真实自然日比例表达。
- 推广页沿用待办、生命周期和历史结构；帖子名称、版本、学科与笔记 ID 使用紧凑行内信息，宽度不足时自然换行，避免强制堆叠挤压指标区；完整 ID 在详情和悬停中可读。缺失 ID 不阻止开始测试，但首次日度复盘必须在行内补填；已有值通过统一确认入口更正。

### 非推广复盘表格

- “待复盘 / 已复盘 / 不复盘”共用同一张高密度表格，一行对应“帖子 × 复盘节点”。列固定为实验日期、帖子、分类、节点、点击率和 3 秒阅读率。
- 帖子名称是行内主视觉锚点并直接链接项目文档；缺失链接时在名称下显示“项目文档待补”，不增加文档列。笔记 ID 在悬停与 Inspector 中提供完整值，主表仅保留紧凑版本信息。
- 点击率和 3 秒阅读率右对齐并使用等宽数字，主值与 pp 差值同一行，同类均值和样本量位于第二行；轮次由节点列明确表达，悬停保留该轮完整说明。正向、中性、负向仅改变差值文字颜色，不使用整格高饱和背景。
- 节点只显示紧凑的“首轮 / 二轮”中性标签，不重复页面视角已经表达的完成状态。桌面端整行点击或键盘打开右侧 Inspector，移动端 Inspector 占满屏幕并支持 Esc 关闭与清晰焦点。
- 最新生命周期按每个推广帖最后一条已填写日度事实截止，只展示仍处于测试或放量中的活动；不因未填写日期继续增长，也不展示已经结束或淘汰的活动。历史活动统一进入“历史总览”。
- 生命周期不使用共享月份网格、逐日日期、垂直游标或数据圆点；卡片上方直接显示阶段天数、是否进行中和完整起止日期，卡片下方以占满整行的比例条表达阶段关系。
- 测试期统一使用黄色 `#D49A12 / #FFF1BF / #6A4A00`，放量期统一使用绿色 `#3F9272 / #DDF2E8 / #205D48`；该规则同时适用于生命周期、日度阶段、历史状态和排期管理中的推广状态。
- 淘汰和正常结束必须显示明确文字，不只依赖颜色。
- 日度录入区是待办队列，不显示已经填写的日度事实。当前活动截至昨天的连续漏填日期全部列出，只有最早未填日期可编辑，后续日期明确提示需先完成哪一天；五项手动指标统一输入规格，两项自动成本用只读数值成组展示，桌面相邻分区，窄屏自然重排。
- 当日状态沿用前一天安排，测试／放量行内允许改为“当日暂停”，选择后才显示暂停原因与截止日；暂停不要求 ID 或数字，切换后收起指标与原下一步输入，显示带标签的暂停截止日与区间预览；切回保留全部草稿。下一步单独决定次日。旧逐日等待事实继续读取，新待定使用独立区间，不补造零指标。
- 推广历史详情遵循下方共享 Inspector 规范；左侧历史列表不得横向溢出或透出到详情下方。
- 日度复盘不填写或展示点击率；平台口径与实际口径并列，字号、行高和列宽保持一致，不用换行制造层级。桌面端日度行不得依赖横向滚动，窄屏改为自然重排。
- 首次安排、持续状态与日度数据共用待完成复盘的行宽、留白、边框与控件规格。首次安排用“YYYY-MM-DD 的安排”与三选一、保存同行表达，三选一为待定（未开始推广）、开始测试、直接放量；待定截止日必须有可见标签，选择时预览完整区间与下次复盘，开始测试／直接放量直接回到数据录入。
- 待定／暂停行头部只显示阶段对应的短状态，摘要显示带标签的起始日、含当天的截止日及天数；未到期显示下次复盘日，到期后直接显示截止日次日的安排选项与保存，不重复解释生效日期。区间覆盖每个自然日，行内可展开逐日状态记录；长区间合并中间连续范围。修改状态、调整截止日与记录按钮位于本条头部，编辑器在本条内部展开并保留草稿；未保存不自动延长截止日。
- 日度数据按帖子／数据日期／当日状态、原始指标与计算成本、下一步与保存组织。状态标签与选择行内对齐；五项输入与两项成本通过轻分隔区分，成本无输入边框且不占用输入框高度，不增加说明标题。下一步选择和完成复盘组成紧邻、从左开始的操作单元，首次笔记 ID 就近排列，空反馈不占位；窄屏整组重排，字体和控件尺寸保持不变。暂未解锁的日期明确为“待前日复盘”，不混用“待定”表示尚未确认阶段。
- 当排期实发日期或推广身份变化会清空既有推广事实时，必须先明确显示受影响活动和日度记录数量，再要求二次确认。
- 推广帖复盘顶部只有“每日复盘 / 阶段复盘”。每日包含最新生命周期、待定区间和未完成复盘；待完成标题旁提供历史总览入口和返回每日的路径。历史默认全部记录，日期可选，并可切换帖子视角与日视角。帖子视角将测试中、放量中的活动置顶，已结束活动默认折叠，右侧 Inspector 展示生命周期、逐日事实和历史编辑入口；日视角按日期倒序分组，在组头汇总四项核心数据，每篇帖子占一行。长期数据不铺成横向日历。
- 历史编辑器只开放消耗、四项人数、备注和下一步，系统身份字段不伪装成可编辑表单。修改下一步会影响后续事实时，确认文案必须明确后续记录会被删除并重新回到待填队列。

### 非推广阶段复盘

- 主内容使用高密度数据表，一行对应“帖子 × 复盘节点”；低价值列压缩，帖子名称和点击率、3 秒阅读率获得主要宽度，笔记 ID 不独立占列。
- 点击率和 3 秒阅读率并列同权展示。主值使用深色等宽数字，与 pp 差值同一行；正向、中性、负向仅使用低饱和绿、灰、红差值文字，同类均值和样本量另行显示，轮次由节点列明示。
- 分类默认规则属于全局设置，只从 Sidebar 主导航末尾“系统管理”分组的“系统设置”进入，不出现在复盘工作流中；推广转非推广仍使用原因输入和明确影响说明。
- 内容标题直接链接到排期版本的项目文档 URL；缺少 URL 时明确显示“项目文档待补”，不制造不可点击的链接。
- 主表节点只使用紧凑的“首轮 / 二轮”中性标签，不重复页面视角已经表达的完成状态。右侧 Inspector 的数据截至、点击率和 3 秒阅读率保持同一录入结构；窄屏再自然重排。
- 周会非推广推荐榜分为“本周推荐 / 其他可选”；勾选单位是首轮或二轮节点。每项同时显示指标是否完整和已进入定稿周会的次数，已复盘节点仍可再次勾选。

- 非推广筛选使用相邻的学科与帖子分类控件；切换学科清除不匹配分类，视图与 Inspector 切换保留筛选。跳过及恢复在 Inspector 独立表单操作，原因必填，不受指标输入要求影响。
- 排期待办提醒位于共享侧栏顶部，优先显示“尚未登记 N 篇”，手机在排期导航显示数量；未登记不直接视为漏发，不重复计入待补原因。改期审批与逐日理由沿用 Inspector，历史明细和已处理审批默认折叠。

### 年度总周期规划

- `THE PLAN` 默认在一个页面纵向展示总规划和所有学科细致规划，使用冻结的分区、SOP/帖集和规划项目列以及 1—12 月年度矩阵。
- 总规划使用独立只读汇总带，与可编辑细致规划建立明确上下层级；桌面端在 1280px 及以上应同时看清完整 12 个月。
- 总规划与细致规划共享同一组固定业务列和 12 个月份轨道：总规划的科目跨越规划分区与 SOP 两列，周期对应规划项目列；横向滚动、分区筛选和停用状态切换不得改变月份起点。
- 1、4、7、10 月使用更明确的季度起点分隔；季度节奏只帮助读取年度，不新增业务状态。
- 规划分区、SOP 和规划项目列按顺序冻结；SOP 只承担箭头入口，规划项目承担名称和版本状态。sticky 层级依次为月份内容、固定数据列、月份表头和交叉表头，不允许相互透底或覆盖。
- 时间块按半月起止；保留 12 个月表头，月份内部使用低存在感的月中分隔。矩阵条幅直接显示用户填写的备注，长备注最多两行并在 Inspector 完整呈现，不显示乘法、加法或问号。
- 科目使用稳定色相：TMUA 蓝、STEP 紫、面试课橙；深色表示付费推广，浅色表示非推广、观察或自然流，同时提供文字图例。付费状态不由数量或分类强制决定。
- 同一周期保持一条连续条幅，付费子区间与自然流子区间分段着色；混合条幅使用清晰的备注文字层，不能因背景深浅影响文字可读性。总规划、主矩阵和缩略轨道共享半月比例与色彩含义。
- 桌面端和移动端都允许年度矩阵横向滚动，不把 12 列压缩到不可读；窄屏编辑器使用全屏或重排布局。
- 规划详情沿用 Inspector，新建与编辑沿用 Sheet/Dialog；选中规划时固定业务列和月份轨道形成连续整行反馈。
- Inspector 按“规划身份 → 当前状态 → 年度缩略轨道 → 时间块 → SOP → 备注 → 版本历史”组织，并与主矩阵共享月份比例和学科色。版本历史沿用工作台正文、辅助信息和中性次级按钮，日期使用北京时间 `YYYY-MM-DD HH:mm`；动态加载的历史和版本内容保持相同字体层级。
- Inspector 时间块显示阶段名称、半月范围、完整备注及分段推广状态；窄屏允许自然换行，不用失衡的固定列挤压中文内容。
- 年度矩阵的规划项目列将名称、版本号和停用状态放在同一行；分类关系在 Inspector 中查看，不在矩阵中重复形成第二行。
- 分区、SOP 和规划项目列保持紧凑；SOP 使用可访问的箭头链接。时间块编辑按半月范围、自由备注、推广安排和可选阶段说明组织，提供即时预览；年度复制使用轻量 Dialog。

## 首页概念：内容穿越总控台

首页的标志性场景是一张呈现完整前端工作流的内容工作台。

- 大量 3:4 帖子封面分布在不同深度、位置和角度。
- 用户正常滚动页面时，封面从远处向前靠近并从视野边缘离开。
- 封面的速度、位置和旋转可以不规则，但不能遮挡核心宗旨文字。
- 同时只允许少量封面完全清晰；远处封面降低亮度并增加轻微模糊。
- 封面层与首屏全部文字、轨道之间使用覆盖整个视口的统一深色遮罩，不再为局部文字区域单独叠加遮罩。
- 六条轨道表达策划、内容、视觉、发布、用户触点和复盘如何依次衔接并持续回流。
- Hero 在同一画面内并列呈现“工作平台是什么”和“内容为了什么”：左侧为工作台定位，右侧以 `WHY WE EXIST` 标记使命句，下方用箭头连接点击、读完与咨询目标；不再设置独立的使命区块。
- Hero 的信息层级以主标题为第一焦点，使命为第二焦点，行动路径和流程轨道作为辅助层；避免标题、使命、目标和轨道同时使用最高对比度。
- 六阶段当前环节驱动低强度环境光变化：策划、内容、视觉、发布、触点和复盘依次使用蓝、靛、紫、珊瑚、薄荷和冷蓝光场；光场只增强空间连续性，不替代文字状态。
- 封面上方继续使用全屏统一遮罩，但由局部阅读暗角、底部轨道暗角和轻量纵向渐变共同组成，不再用单层黑色透明度压暗全部素材。
- Hero 结束后由浅蓝灰工作流区按正常文档流承接深色场景，系统入口保持明亮列表结构；第二页不得使用负边距、顶部圆角或向上阴影覆盖 Hero 内容。
- 大胆程度集中在这个场景，离开 Hero 后停止 3D 穿越效果。

## 必须保留的内容宗旨

- 让用户愿意点击；
- 让用户愿意读，且愿意读完；
- 让用户愿意进一步了解与咨询。

宗旨必须使用网页文字呈现，不写入生成图片，保证准确、清晰和可访问。

## 首页视觉变量

- `Control Night #0B1B2B`：Hero 基础空间与页脚；
- `Signal White #F5F7F4`：页面底色和主要文字；
- `Blueprint #5B8CFF`：Hero 环境光、轨道和结构信息；
- `Marker Coral #FF8A68`：当前流程环节和关键动作；
- `Monitor Mint #9ED8C4`：触点环境光和少量辅助状态；
- `Workflow Mist #E9EFF2`：Hero 后工作流阅读区。

首页标题使用紧凑、强重量、较窄的无衬线表达；正文使用适合中文连续阅读的中性无衬线；编号按需使用等宽字体。工作台遵守前述中文、日期与数字层级，不将中文状态改成等宽字体。未引入外部字体依赖，正式品牌字体后续单独确认。

## 帖子封面

- 正式素材优先使用真实小红书帖子封面。
- 推荐比例为 3:4；组件也以 `aspect-ratio: 3 / 4` 约束。
- 素材应先移除不应公开的信息，不编造业务结果或用户数据。
- 当前使用八张用户提供的真实封面；每张素材只创建一个循环实例，避免同屏重复。
- 代码生成的封面板只作为图片未配置时的备用显示；替换素材不应重写动画。
- 封面从远处向镜头浮现：远景在中间自然错开，近景逐渐放大并向视口四角展开；滚动过程中尽量减少相互重叠。
- 纵深可以制造大小变化，但尺寸差异应保持克制，形成“乱中有序”的稳定节奏。
- 初始画面允许通过内外两层顺时针顺序和轻微渐进尺寸形成静态螺旋感；它只影响初始构图，开始滚动后应平滑回归原有向前展开轨迹，不围绕中心旋转。

## 动效与性能

- 滚轮继续控制正常页面进度，不锁定滚动，不制造强制翻页。
- 使用 CSS 3D 与轻量 React Island 映射滚动进度，不引入大型 3D 库。
- 活跃封面数量保持有限，通过不同深度和循环形成丰富感。
- 流程轨道到达 06 后，封面仍在 Hero 离场过程中继续循环；只有 Hero 完全离开视口后才停止显示。
- 支持 `prefers-reduced-motion`；减少动态效果时保留静态纵深，不持续推进封面。
- 移动端降低封面尺寸、运动强度和轨道密度。
- 桌面端封面场景以 `1440 × 900` 为基准画布，尺寸、位置、透视和运动距离按同一比例整体缩放；宽屏增加居中安全留白，不单独拉伸构图。`820px` 以下使用独立移动端规则。

## 登录与账号反馈

- 保留总枢纽首页视觉，仅增加清晰的登录入口；独立登录页使用现有深蓝、浅蓝灰、系统中文字体和安静表单，不复制 Formward 品牌或人物场景。
- 桌面账号菜单位于共享侧栏底部，手机位于固定高度的工具栏内；菜单使用原生 popover，避免被工具栏或 Inspector 裁切。
- 管理入口随服务端角色显示；年度与排期动作按服务端有效操作权限呈现，员工默认年度只读，关闭的操作不显示为可点击动作。
- 按钮立即显示忙碌并防重复提交；共享提示在等待超过 200ms 后出现，并发操作独立计数。失败保留输入，会话过期提供新标签页重新登录入口；退出以完整导航清除上一账号页面状态。

### 待定区间、阶段快照与例会

- 首次安排与已投放后的待定按业务日期显示，三种首次状态为尚未开始、开始测试、直接放量；区间末日的下一步保持空选项。末日未安排时只保留这一行，不自动延长截止日或累计未来逐日待办。每日测试／放量行内提供当日暂停，切换时保留指标草稿，暂停不要求 ID 或数字。
- 推广历史和排期 Inspector 共用状态编辑器；保存仅刷新本篇业务行与摘要，保留其他帖子草稿、公共表头、工具栏、滚动与选择。历史影响用公共异步确认框列出冲突日期与数量，原始指标可从审计查看。
- 排期待审沿用排期台账的容器、日期分组、版本与状态样式，每条申请独立一行；详情使用共享 Inspector，默认展开首项。原内容与申请内容按字段纵向对照，完整日期与理由无需横向拖动，固定底部提供通过／驳回。设置常规导航仅含业务规则与账号权限，排期审批从排期管理进入。
- 推广每日和阶段属于同一模块，共用持久化顶栏；手机底栏只占一个推广入口。阶段表以帖子与内容版本为锚点，测试黄、放量绿，实际开口／留资及成本并列；来源和平台指标放入展开明细，缺口保留明确文字。
- 阶段快照保留名称、日期、版本和生成时间，采用干净的表格供截图与例会引用。例会按五个业务部分纵向组织，移动端单列；已定稿默认展示冻结内容，编辑另存修订。图片展示受控预览和可见上传进度，链接与图片不替代文字结论。

### 共享正文与 Inspector

- 正文统一使用 `business-console-content` 和 Frame 中的留白变量；页面不得重新声明 `main` 的尺寸、边距或内边距。不同业务表格可有不同结构，公共标题和操作基线保持一致。
- 先检查现有组件和[真实接入示例](code-study.md#共享界面接入)，再实现前端。相邻视图更换内容和选中态，保留共同的工具栏、切换按钮节点；公共坐标与尺寸误差不得超过 1 CSS px。
- 排期、年度规划、非推广与推广历史共用 `BusinessInspector` 和 `business-inspector.ts`；页面只负责业务内容、字段校验和保存，不重写开关动画、键盘或焦点流程。
- 打开详情立即使用页面已加载数据，补充请求仅在面板内显示加载、失败和重试。打开、快速切换和关闭不发起文档导航，不重建左侧列表；保持筛选、排序及滚动位置，异步结果必须检查当前选择，旧响应不能覆盖新选择。
- 桌面详情使用共同宽度、工具栏下方位置和过渡；中等屏宽采用右侧覆盖，手机占用顶部工具栏与底部导航之间的整个工作区。年度矩阵可采用同款覆盖式面板。
- 申请差异由 `BusinessChangeDiff` 与 `business-change-diff.ts` 共用字段结构和样式，每个字段纵向列原内容、申请修改为；主台账的表格宽度与移动端样式限定在列表容器，不得影响详情。
- Inspector 采用保留当前对象名称的固定头部、单一滚动正文和固定底部操作区，容器整体不滚动；正文使用 overscroll containment，历史及表单自然展开，不建立第二条纵向滚动轨道。手机覆盖时锁定背景，关闭恢复位置。排期按帖子摘要、待处理、相关资料、历史组织；待填原因最早一天默认展开，其余折叠，已填与历史独立收纳，删除进入“更多操作”。
- 打开后焦点进入面板，关闭回到触发行；Esc 关闭最上层详情，业务对话框打开时优先处理对话框。手机限制 Tab 在面板内循环；减少动态效果时取消过渡。
- 未保存的编辑在切换记录、关闭、后退或离开时确认；取消后保留输入和当前记录。深链接、刷新和浏览器前进后退都能还原选择。请求失败保留输入，保存后明确反馈；已复盘更正通过认证 GET 刷新列表和同轮基准。

### 非推广已复盘的轮次与分组

- 已复盘提供独立“全部轮次 / 首轮 / 二轮”筛选和“按帖子分组”开关，默认全部轮次且分组。待复盘的业务节点、日期、录入、跳过和恢复流程沿用既有口径。
- 按实发排期（内容版本）分组，不能按标题或逻辑帖子合并；组内首轮在前、二轮在后，缺轮显示“暂无已复盘数据”。默认实发实验日期倒序。
- 两轮分别使用全部历史中同学科、同分类、同轮次的样本，包含当前帖；筛选和分组不改变样本池。差值是当前指标减去该轮均值，单位为 pp，不能跨轮比较。
- 分组且选择全部轮次时只按实验日期排序；选定一个轮次后开放指标排序，保持整个帖子组移动。取消分组后保留逐行排序。
- 分组开关共用同一张六列表格和行结构，列宽、表头、字号、内边距与横向滚动规则一致；不设置独立组头，不插入分组说明。切换仅原位重排已有行，保留筛选、有效排序、滚动、详情与未保存输入；从跨轮指标排序切入分组时恢复日期倒序。缺轮使用同列的只读占位，不进入真实指标和编辑入口。

### 发布登记与月历

- 排期管理默认月历；当月内容、待发和已发筛选保留当前显示方式，跨月待办及推广阶段明细使用台账。月历实际应用筛选，并沿用公共工具栏和 Inspector，切换不改变公共位置。
- 月历卡片底色表达发布状态：按时已发为绿（#DDF2E8 / #205D48）、延期已发为红（#F9E3DF / #913C35）、超时尚未登记为黄（#FFF1BF / #73551D）、正常待发为浅蓝（#E8F0FA / #345679）。推广身份用独立蓝标签（#E0E9FF / #244B9A），非推广为中性灰；状态文字由图例、悬停提示、可访问名称和详情提供。阶段颜色仅用于阶段标签，不覆盖发布底色。
- 月历按应发日期排列。日期按钮和当天空白区域打开共用新做帖 Sheet，预填所选日期、时分留待选择；点击帖子只开详情。日期与时分控件共用同一表单和提交契约，其他新建入口也使用同一组控件。
- 桌面为七列月份网格，手机按同月日期纵向排列。卡片固定两行：推广身份与时间、版本与标题；移除底部重复状态行。标题在桌面、手机及 Inspector 打开后都单行省略，全文由悬停和详情查看。内边距 6px、内部间距 3px、同日卡片间距 4px，桌面日格最小高度 104px，多帖自然增高；键盘提供带日期名称的新建入口。
- 发布 Sheet 只保留发布时间、帖子链接或分享文案、项目文档；未来时间直接登记。帖子输入可粘贴完整文案，原始输入保留，旁边预览识别链接；失败与未保存关闭均保留现有保护。
- 已有发布时间默认只读，管理员勾选更正后开放时间和必填原因。旧记录精确秒数保持不变。允许留空的历史帖子链接区域直接为空，不显示缺失、补链、豁免或初始化说明，也不显示必填标记。
- 旧预约历史只读并默认折叠；不提供预约模式、审核、到点确认和对应通知入口。延期理由沿用 Inspector；排期申请在排期管理的“排期待审”查看并处理，系统设置不重复放入口。既有设置审核地址仅保留兼容访问。
