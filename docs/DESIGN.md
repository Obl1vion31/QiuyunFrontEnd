# 设计方向

## 总体原则

- 首页是全站唯一允许大胆视觉表达的页面。
- 首页后半段和未来业务页面保持简洁、低动效和高可读性。
- 视觉必须服务真实前端工作：内容策划、阅读体验、视觉设计、发布、用户触点和复盘。
- 不用普通卡片网格、装饰性编号或无业务含义的渐变制造“设计感”。
- 中文阅读体验、移动端可用性、键盘焦点和减少动态效果模式属于质量底线。

## 业务页面：高密度运营台账

- 业务页使用低动效、清晰分区和高信息密度，不复制首页的 3D 穿越效果。
- 业务页吸收 Apple Design 的界面原则而不是仿制 macOS：桌面端以垂直导航和上下文工具栏组织层级，移动端自适应为紧凑 Bar；按下即反馈，弹层从触发关系中产生并沿原路径关闭。
- 同属“内容发布控制台”的页面必须共享同一应用壳层，不得分别复制并修改 Sidebar、Toolbar 和移动端导航 CSS。新增业务页面应复用统一 Layout / 组件；已有页面出现差异时优先收敛公共壳层，不在单页继续打补丁。
- 半透明材质只用于浮动工具栏、弹层等功能性上层，表格和密集数据区保持实色与清晰对比；不以毛玻璃代替信息层级。
- 帖子版本是业务结构，不是装饰编号：V0 表示新做帖，V1 及以后表示从原版本派生的改帖。
- 排期页采用 `Sidebar + Toolbar + Inspector + Sheet` 的工作台结构；桌面端左侧导航保持稳定，主区承载紧凑时间轴台账，选中内容后在右侧检查详情和版本关系。
- 排期与推广状态共用同一份按日分组的紧凑时间轴数据，不建设相互割裂的推广看板；状态带提供本月内容、待发布、推广中、测试中、放量中、逾期未发和已发布视角，其中“推广中”明确拆分测试与放量数量。
- 台账与月历是同一批数据的两种表达；新增、编辑和改帖统一使用右侧 Sheet，移动端使用全屏形式。
- “推广周期已结束”“测试淘汰”和“放量淘汰”使用不同文字标签，三者均不进入当前推广状态带。
- 月份标记、表头、状态标签和日期用于编码真实业务信息，不作为装饰编号。
- 延期发布、逾期未发、数据库异常和字段错误必须有明确文字，不能只依赖颜色。
- 表单保留可见标签、键盘焦点和字段级错误；横向信息表格在窄屏可滚动，不压缩到不可读。
- 学科与帖子分类使用相邻的两级选择控件；帖子分类只显示当前学科下的有效选项，切换学科时清除不再匹配的分类。
- 面试课新建或编辑内容时必须从七项有效分类中选择；历史空分类记录仍按“面试课”显示，不额外展示“未分类”。
- 创建改帖只保留“具体改动说明”，输入框下方以简短说明示例提示“改动了哪些部分”以及“改动原因和希望达到的效果”，不增加额外装饰。
- 完成情况在表单中作为系统计算结果展示，不提供手动状态选项；延期原因仅在实发超过应发 12 小时时展开并设为必填。
- Inspector 和 Sheet 必须管理初始焦点、Esc 关闭与未保存提醒；移动端 Inspector 和 Sheet 使用全屏形式，控制台已实现入口收纳为底部 Bar。
- 沿用 `Control Night`、`Blueprint`、`Marker Orange` 和 `Monitor Mint`，但把大胆表达留给首页。

### 内容发布控制台统一壳层

年度总周期规划、排期管理、推广日度复盘、非推广阶段复盘、例会复盘和系统设置属于同一个应用。所有页面使用同一个共享 Sidebar 组件；跨页面切换时，只有主内容和当前导航状态可以变化，外围框架不得跳动或换色。

- 桌面 Sidebar 固定使用同一宽度、背景色、内边距、品牌区高度、导航行高度、圆角、图标尺寸、激活态和底部区域。具体尺寸与色值以当前统一壳层实现为准，可以根据跨页体验继续调整；不得因模块主题单独换色或改变主内容起点。
- 顶部 Toolbar 固定使用同一高度、左右内边距、底色、边框和三列对齐基线。具体高度由跨页面实际信息密度共同确定，可以继续试调；中间筛选或切换控件不得单独把整条 Toolbar 撑高。
- 当前 Toolbar 桌面端固定为 `72px`、移动端固定为 `62px`，横向占满 Sidebar 右侧 Workspace；标题、年月导航、分段切换、汇总和操作按钮均使用共享组件，单页不得覆盖其字体、颜色或几何。
- Toolbar 左侧信息统一为“模块主标题 + 当前上下文”两行结构。主标题的字号、字重、行高一致；第二行只承载年份、月份、视角或截止日期等上下文。`THE PLAN`、`Daily Promotion Review` 等英文可以作为辅助名称，但不能改变标题区高度和基线。
- Toolbar 中部用于当前页面的日期导航、视角切换或阶段切换，右侧用于汇总和主要动作。某页没有对应内容时保留网格对齐，不用改变整体高度补偿。
- Toolbar 中部只允许单行控件。推广日度复盘的数据截止时间并入左侧副标题，不能在中部叠加第二行并撑高顶栏。
- 移动端统一使用同一底部导航高度、背景、图标和安全区规则；Toolbar 的移动端高度、标题折叠方式和主要操作位置也必须一致。
- 页面专项色只进入内容区的数据编码，例如学科色、测试黄和放量绿；不得改变 Sidebar 或 Toolbar 的基础色。
- Sidebar 必须形成完整的样式隔离边界：组件根节点及全部后代统一声明 `box-sizing: border-box`，并由组件显式声明字体族、基础字号和行高。不得让 Sidebar 继承页面级 `* { box-sizing }`、`body` 字体或 `body` 行高；否则 scoped 与 global 页面会把同一导航行计算成不同高度。
- 业务页面只能引用共享 Sidebar 并传入当前激活项，不得声明 `.sidebar`、`.module-nav`、`.sidebar-foot` 等独立侧栏结构或样式。修改 Sidebar 只进入共享组件；右侧 Workspace 的样式不得命中共享侧栏命名空间。
- Sidebar 以“计划与执行 / 复盘与沉淀”表达真实业务分组，导航使用单行中文名称和语义线性图标。当前项保持完整圆角选择面；hover、键盘焦点、按压和加载必须各自可辨，但不得通过图标弹跳、整页淡入或分散动效制造反馈。
- 跨页面切换时 Sidebar 持续存在，点击先更新当前项；只有等待超过短暂阈值才在 Toolbar 下缘显示单一加载条。预取只由 hover、键盘 focus 或触摸按下触发单个目标，不在页面打开时请求全部模块。
- 验收业务页时必须连续点击所有控制台模块，检查 Sidebar、Toolbar、主内容左边界和首屏垂直起点是否逐页保持不动。单独截图看似合理但跨页跳动，仍视为不合格。

壳层参数属于实现细节，不作为永久设计结论；长期结论是同一控制台的所有页面必须使用相同参数和信息结构。发现跨页差异时应通过共享壳层一次性消除，不把某次试调值继续复制到新页面。

控制台页面结构统一由 `BusinessConsoleFrame`、`BusinessConsoleToolbar`、`BusinessPageHeader` 和 `BusinessSectionHeader` 组合。页面级标题采用“英文眉题 + 中文主标题 + 一句必要说明”的固定层级；需要页面级标题时必须同时提供英文眉题，不在卡片、表单或弹层中散落装饰性英文。紧凑台账页可以直接从工具栏进入内容，不强制增加页面级标题。

- 页面标题只说明当前工作对象与必要边界，不重复操作顺序、到期规则或显而易见的步骤。
- 区块标题使用共享 Section Header；标题、说明和右侧计数的字号与间距不得由单页重新定义。
- 相同层级的 Bar 使用共享 Toolbar；页面只通过命名插槽提供日期导航、视角切换、汇总和主要动作。
- 新业务页面优先组合上述组件。只有信息结构确实不同且无法通过组件 Props 或插槽表达时，才新增视觉结构。

### Daily Promotion Review

- 推广日历只表达推广帖，不混入非推广内容；每篇帖子使用一张独立的全宽生命周期卡片，阶段宽度按截止日内的真实自然日比例表达。
- 最新生命周期按每个推广帖最后一条已填写日度事实截止，只展示仍处于测试或放量中的活动；不因未填写日期继续增长，也不展示已经结束或淘汰的活动。历史活动统一进入“历史总览”。
- 生命周期不使用共享月份网格、逐日日期、垂直游标或数据圆点；卡片上方直接显示阶段天数、是否进行中和完整起止日期，卡片下方以占满整行的比例条表达阶段关系。
- 测试期统一使用黄色 `#D49A12 / #FFF1BF / #6A4A00`，放量期统一使用绿色 `#3F9272 / #DDF2E8 / #205D48`；该规则同时适用于生命周期、日度阶段、历史状态和排期管理中的推广状态。
- 淘汰和正常结束必须显示明确文字，不只依赖颜色。
- 日度录入区是待办队列，不显示已经填写的日度事实。当前活动截至昨天的连续漏填日期全部列出，只有最早未填日期可编辑，后续日期明确提示需先完成哪一天；六项原始数据与两项自动成本在同一行对齐。
- 日度复盘不填写或展示点击率；平台口径与实际口径并列，字号、行高和列宽保持一致，不用换行制造层级。桌面端日度行不得依赖横向滚动，窄屏改为自然重排。
- “待开始推广”使用中性蓝灰待办行，与测试黄、放量绿明确区分；当日未推广与开始测试是同一行的两个明确动作，不把未推广日期画入测试生命周期。
- 当排期实发日期或推广身份变化会清空既有推广事实时，必须先明确显示受影响活动和日度记录数量，再要求二次确认。
- Daily Promotion Review 以“每日复盘 / 历史总览”切换组织当前工作和历史检索。每日复盘只承载最新生命周期和未完成复盘，已填事实不允许通过日期切换返回当前工作区；历史总览默认 90 天并可切换帖子视角与日视角。帖子视角将测试中、放量中的活动置顶，已结束活动默认折叠，右侧 Inspector 展示生命周期、逐日事实和历史编辑入口；日视角按日期倒序分组，在组头汇总四项核心数据，每篇帖子占一行。长期数据不铺成横向日历。
- 历史编辑器只开放消耗、四项人数、备注和下一步，系统身份字段不伪装成可编辑表单。修改下一步会影响后续事实时，确认文案必须明确后续记录会被删除并重新回到待填队列。

### 非推广阶段复盘

- 每篇候选内容以一张复盘卡承载身份、T+7 / T+15 双节点轨道、当前指标、同类基准和人工结论；轨道顺序是真实时间顺序。
- 节点状态同时使用文字和视觉区分未到期、本期到点、继续结转与已确认。点击率和 3 秒阅读率并列同权展示，同类样本范围置于指标下方。
- 分类默认规则属于全局设置，只从 Sidebar 左下角“系统设置”进入，不出现在复盘工作流中；推广转非推广仍使用原因输入和明确影响说明。
- 内容标题直接链接到排期版本的项目文档 URL；缺少 URL 时明确显示“项目文档待补”，不制造不可点击的链接。
- T+7 / T+15 使用紧凑等宽分段轨道，数字不得作为孤立的大号装饰。桌面端的数据截至、点击率和 3 秒阅读率保持同一录入行，标签固定在控件上方；窄屏再自然重排。

### 年度总周期规划

- `THE PLAN` 默认在一个页面纵向展示总规划和所有学科细致规划，使用冻结的分区、SOP/帖集和规划项目列以及 1—12 月年度矩阵。
- 总规划使用独立只读汇总带，与可编辑细致规划建立明确上下层级；桌面端在 1280px 及以上应同时看清完整 12 个月。
- 总规划与细致规划共享同一组固定业务列和 12 个月份轨道：总规划的科目跨越规划分区与 SOP 两列，周期对应规划项目列；横向滚动、分区筛选和停用状态切换不得改变月份起点。
- 1、4、7、10 月使用更明确的季度起点分隔；季度节奏只帮助读取年度，不新增业务状态。
- 规划分区、SOP 和规划项目列按顺序冻结；SOP 只承担箭头入口，规划项目承担名称和版本状态。sticky 层级依次为月份内容、固定数据列、月份表头和交叉表头，不允许相互透底或覆盖。
- 时间块跨越连续月份；矩阵条幅内只显示 `1×4`、`3+3+4` 等数量规则，不重复阶段名称。阶段名称完整保留在规划项目、Inspector、编辑器和悬停说明中；数量待确认时在条幅内显示 `?`。
- 弹性频次、硬性数量组合和数量待确认的时间块同时使用文字和视觉样式区分，Inspector 明确写出“数量待确认”，空月份保持低存在感。
- 时间块颜色只编码科目：TMUA 蓝、STEP 紫、面试课橙；数量规则不再改变深浅或色相。
- 弹性频次、硬性组合和 `?` 在主矩阵使用同一字号与字重，不因规则类型制造无业务含义的视觉等级。
- 桌面端和移动端都允许年度矩阵横向滚动，不把 12 列压缩到不可读；窄屏编辑器使用全屏或重排布局。
- 规划详情沿用 Inspector，新建与编辑沿用 Sheet/Dialog；选中规划时固定业务列和月份轨道形成连续整行反馈。
- Inspector 按“规划身份 → 当前状态 → 年度缩略轨道 → 时间块 → SOP → 备注 → 版本历史”组织，并与主矩阵共享月份比例和学科色。版本历史保留现有结构，后续只在真实使用暴露明确问题时单独优化。
- Inspector 时间块名称、数量规则与月份范围必须处于同一水平基线：名称优先保持单行并占据主要宽度，数量紧随名称，月份范围稳定靠右且不换行；只有备注进入次级行。不得使用两个失衡的固定列把短名称或数量挤成多行。
- 年度矩阵的规划项目列将名称、版本号和停用状态放在同一行；分类关系在 Inspector 中查看，不在矩阵中重复形成第二行。
- 分区、SOP 和规划项目列保持紧凑；SOP 使用可访问的箭头链接。时间块编辑按月份范围、可选阶段说明和互斥数量规则组织。

## 首页概念：内容穿越总控台

首页的标志性场景是一张呈现完整前端工作流的内容工作台。

- 大量 3:4 帖子封面分布在不同深度、位置和角度。
- 用户正常滚动页面时，封面从远处向前靠近并从视野边缘离开。
- 封面的速度、位置和旋转可以不规则，但不能遮挡核心宗旨文字。
- 同时只允许少量封面完全清晰；远处封面降低亮度并增加轻微模糊。
- 封面层与首屏全部文字、轨道之间使用覆盖整个视口的统一深色遮罩，不再为局部文字区域单独叠加遮罩。
- 六条轨道表达策划、内容、视觉、发布、用户触点和复盘如何依次衔接并持续回流。
- Hero 在同一画面内并列呈现“工作平台是什么”和“内容为了什么”：左侧为工作台定位，右侧以 `WHY WE EXIST` 标记使命句，下方用箭头连接点击、读完与咨询目标；不再设置独立的使命区块。
- Hero 的信息层级以主标题为第一焦点，使命为第二焦点，行动路径和流程轨道作为辅助层；避免标题、使命、目标和轨道同时使用最高对比度。
- 六阶段当前环节驱动低强度环境光变化：策划、内容、视觉、发布、触点和复盘依次使用蓝、靛、紫、珊瑚、薄荷和冷蓝光场；光场只增强空间连续性，不替代文字状态。
- 封面上方继续使用全屏统一遮罩，但由局部阅读暗角、底部轨道暗角和轻量纵向渐变共同组成，不再用单层黑色透明度压暗全部素材。
- Hero 结束后由浅蓝灰工作流区按正常文档流承接深色场景，系统入口保持明亮列表结构；第二页不得使用负边距、顶部圆角或向上阴影覆盖 Hero 内容。
- 大胆程度集中在这个场景，离开 Hero 后停止 3D 穿越效果。

## 必须保留的内容宗旨

- 让用户愿意点击；
- 让用户愿意读，且愿意读完；
- 让用户愿意进一步了解与咨询。

宗旨必须使用网页文字呈现，不写入生成图片，保证准确、清晰和可访问。

## 视觉变量

- `Control Night #0B1B2B`：Hero 基础空间与页脚；
- `Signal White #F5F7F4`：页面底色和主要文字；
- `Blueprint #5B8CFF`：Hero 环境光、轨道和结构信息；
- `Marker Coral #FF8A68`：当前流程环节和关键动作；
- `Monitor Mint #9ED8C4`：触点环境光和少量辅助状态；
- `Workflow Mist #E9EFF2`：Hero 后工作流阅读区。

## 帖子封面

- 正式素材优先使用真实小红书帖子封面。
- 推荐比例为 3:4；组件也以 `aspect-ratio: 3 / 4` 约束。
- 素材应先移除不应公开的信息，不编造业务结果或用户数据。
- 当前使用八张用户提供的真实封面；每张素材只创建一个循环实例，避免同屏重复。
- 代码生成的封面板只作为图片未配置时的备用显示；替换素材不应重写动画。
- 封面从远处向镜头浮现：远景在中间自然错开，近景逐渐放大并向视口四角展开；滚动过程中尽量减少相互重叠。
- 纵深可以制造大小变化，但尺寸差异应保持克制，形成“乱中有序”的稳定节奏。
- 初始画面允许通过内外两层顺时针顺序和轻微渐进尺寸形成静态螺旋感；它只影响初始构图，开始滚动后应平滑回归原有向前展开轨迹，不围绕中心旋转。

## 动效与性能

- 滚轮继续控制正常页面进度，不锁定滚动，不制造强制翻页。
- 使用 CSS 3D 与轻量 React Island 映射滚动进度，不引入大型 3D 库。
- 活跃封面数量保持有限，通过不同深度和循环形成丰富感。
- 流程轨道到达 06 后，封面仍在 Hero 离场过程中继续循环；只有 Hero 完全离开视口后才停止显示。
- 支持 `prefers-reduced-motion`；减少动态效果时保留静态纵深，不持续推进封面。
- 移动端降低封面尺寸、运动强度和轨道密度。
- 桌面端封面场景以 `1440 × 900` 为基准画布，尺寸、位置、透视和运动距离按同一比例整体缩放；宽屏增加居中安全留白，不单独拉伸构图。`820px` 以下使用独立移动端规则。
