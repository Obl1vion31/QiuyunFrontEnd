# 设计方向

## 总体原则

- 首页是全站唯一允许大胆视觉表达的页面。
- 首页后半段和业务页面保持简洁、高可读性；业务动效按工作区与展示区分别判断。
- 视觉必须服务真实前端工作：内容策划、阅读体验、视觉设计、发布、用户触点和复盘。
- 不用普通卡片网格、装饰性编号或无业务含义的渐变制造“设计感”。
- 中文阅读体验、移动端可用性、键盘焦点和减少动态效果模式属于质量底线。

### 湫云站点图标

- 采用用户确认的 E3 云形翻转带纯图形，深蓝配青绿；站点图标不带“湫云”、拼音或方案编号。透明 SVG 为主文件，PNG 与各平台尺寸从同一矢量源导出。
- 首页、登录与工作台通过 `SiteIcons` 共用 SVG／ICO favicon 和 Apple 图标；小尺寸站点入口用白色底板保持深浅浏览器主题可读，公开下载的主图保持透明。

### 工作台的一致性基准

- 紧凑与秩序同时验收：相邻记录共用内容起点、标签与控件基线，同一行按统一列宽和间距组织。留白用于必要分组，不以两端分散排列拉大信息距离，也不为紧凑牺牲可读宽度。主动评估能帮助理解状态和操作结果的微交互，在已有设计中补充，实际检查后修正。
- 先确定语义：业务信息、状态、筛选、展示方式、选项与动作按阅读和操作关系分组，再安排视觉结构。统一空间尺度与组件规则，允许日历、矩阵、表格和表单按功能采用不同结构与密度。
- 全局同步、局部例外：公共模式优化前查找整个工作台的全部消费者，同步适用组件、页面、规则与验收；用户明确限定局部时遵从限制。不扩大到无关业务，不机械复制旧例外。

- 整个工作台共用一套产品界面。结构、视觉、组件、信息层级、交互反馈与不同状态均以共享实现为基准；已有页面中的例外须核对后再复用，不因存在而自动成为规范。
- 局部操作，局部变化。筛选、排序、分组、视图切换及展开收起只调整功能必需的内容，保留公共位置、尺寸、节点及阅读连续性；内容组织变化不能连带更换整张表格或插入说明区域。
- 保存反馈与再次编辑分开：成功回执说明本次写入结果，不能替代业务允许的“修改”入口。区分正常状态推进与已录错事实的更正，是否可恢复由业务规则与服务端复核；再次更正保留已填数据、仍合法的选择、触发位置与焦点，不因一次保存永久锁死可更正内容。
- 复用以操作目的为先：资料查看采用就近的链接／只读气泡，完整编辑、历史与审批按任务选择面板。数据、校验、状态规则与保存能力可以共享，表格、卡片和详情不必复制表单 DOM 或保持同形；新增入口须有独立业务价值。验收包含入口必要性、重复操作与内容组织，测试可运行不等于交互合理。
- 同类数据与操作目的先统一输入模式和行为，再统一外观；日期时间、单选、多选、搜索、筛选与切换都按此判断。导航到不同数据视图与原位调整展示方式允许采用符合其语义的不同控件，不能只因外形相近而机械合并。
- 工作台自托管固定 MiSans 5.0.0 Normal VF 及小米字体许可，中文字体回退为 `"MiSans VF", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`，正文基准 14px／22px、辅助信息 12px／18px；共享组件按语义选择层级，不能只修改 CSS 字重而不检查实际字体。
- 字体加载优化必须保留已确认的MiSans、字号和字重，不能以整页锁定系统字体换取“不跳动”。首屏常用原始字体切片随共享静态资源到达，并在正文绘制前准备好原字形，保持可变字重与unicode-range，其他字形按需读取；原始资产及PDF独立保留。验收同时要求首屏稳定和实际字形正确，与原版截图对照，不以字体声明或任何一种稳定回退代替。
- 工作台字体基准由共享变量与语义组件维护，实际字体优先简体中文无衬线，禁止以未核对的默认回退替代验收。页标题 24px／600，区块与详情标题 18px／600，推广概览名称 15px／500、录入行名称 14px／500，业务日期 13px／500，正文与输入 14px／400，字段标签与状态 13px，辅助信息 12px／400；推广累计金额 14px／500、只读成本组 12px／500、非推广分类均值 18px／500，实际非推广结果保持 20px／500。侧栏普通导航 14px／500、选中 600，移动导航沿用紧凑规格。数字使用 tabular-nums，只有原始 ID 与代码使用等宽字体，不整体加粗或调细。
- Inspector 底部动作复用共享操作区：主要动作蓝底，次要动作中性白底，40px 控件、14px／500 文字、8px 间距。灰色外观不等于禁用，实际状态以 disabled／aria-disabled 和可执行业务条件判断。
- 日期和普通中文使用正文字体；数字对齐优先使用 `tabular-nums`，代码或原始 ID 才按需要使用等宽字体。空态、版本历史、弹层及异步加载的内容同样适用，不能依赖浏览器默认按钮字体。
- 业务文案不展示开发思路或实现过程，不重复按钮、筛选和表头已经表达的信息；说明是可选的，仅保留理解和正确操作所必需的业务信息。加载、保存、错误反馈与必要的影响确认继续保留。
- 日期操作直接写明确的目标业务日，避免“某日之后”再补一段生效日期。密集行内的日期标签、选项与保存按同一阅读顺序就近排列，桌面同行对齐，窄屏按完整字段组换行。短状态不拆字；同一状态或日期不通过多个说明段重复表达，详细记录按需展开。
- 控件、颜色、边框、圆角和阴影复用现有共享基准，不因新增功能另建一套；确需突破规范时先说明功能理由并获得用户确认。交付前检查跨页协调、组件及反馈一致、布局跳动、冗余内容和修改范围。

### 控件、筛选与表单抽屉

- 常规表单显式接入 `business-form`、筛选接入 `business-filter`，共享 `src/styles/business-forms.css`；密集行内指标与月份矩阵保留适合其内容的规格，不用全局元素重置强行套用表单结构。
- 完整时间统一通过 `businessDateTime` 显示为上海时区 `YYYY-MM-DD HH:mm`，仅日期通过 `businessDate` 显示 `YYYY-MM-DD`；SSR、异步详情、历史和回显均复用。月历格内有明确日期上下文时可显示时分短格式。完整日期时间统一复用 `BusinessDateTimeFields` 的独立原生日期与时间选择，日期在左、时间在右；仅日期仍使用日期控件。原字段通过共享控制器拼合提交，名称、必填、默认值、只读／禁用及既有服务端时间解析沿用各业务，不使用 `datetime-local` 或普通文本替代同类时间输入。
- 可编辑控件使用白底实线；只读／禁用控件使用浅底与虚线，系统状态用文字或状态标识，不伪装为可编辑字段。必填与错误沿用实际字段校验，空反馈不占位。
- 居中编辑和轻量任务使用 `BusinessFormDialog`，按内容选择宽度；共享头部、滚动正文和固定操作区，与 Sheet 共用表单规范，保留各自出现位置和现有标题栏配色。
- 表单控件与按钮常规高度 40px，筛选与展示方式使用 36px 紧凑规格；同一区域按同一基线、尺寸和间距排列。必填标识与字段标签同行，标签与控件间距 6px，相关字段分列时等宽，字段组间距 16px；字号与颜色使用共享变量，不依赖浏览器默认字体。
- 筛选条件组成一组，展示方式组成独立操作组。两个互斥展示模式使用 `BusinessViewSwitch` 原生单选分段控件，保留键盘、焦点和 URL 状态，不将其伪装成业务属性复选框。现有顶栏继续复用专用 Toolbar 控件，不通过单页覆盖改变其几何。
- 编辑类表单抽屉使用 `BusinessFormSheet`：桌面宽度 680px，900px 及以下占满屏幕，头部与底部固定、只有内容区滚动，底部计入安全区。保持已有深蓝色标题栏配色，标题、版本和关闭操作各自承担实际信息；业务内容通过插槽接入，数据、权限与未保存保护由原业务适配器处理。
- 编辑排期按内容名称整行、学科／分类并排、日期／时间并排、推广与朋友圈同组选项、项目文档整行排列。发布登记沿用相同标签、输入、日期、选项与按钮规格；具体字段不同不改变容器规范。空校验信息不占位，必要权限、错误与影响说明保留。
- 表格与容器按真实内容自然增高，不为少量数据撑出整屏空白；窄屏滚动局限在表格内部。重复 ID 等低优先级信息可移到悬停和详情，版本及轮次须清晰保留；主指标与差值并列、同类均值及样本量另行显示，避免重复轮次标签。

### 异步交互与加载反馈

- 区分读取、后台刷新、导航与写入。来源卡片在详情读取中保持原文、状态色、尺寸与可用性，不以最近点击元素推断加载按钮。读取先显示已知摘要，500ms 内不显示加载文案或动画；超过时只在目标容器（Inspector、历史、筛选结果或局部刷新区）显示一处加载状态，关闭操作始终可用。
- 侧栏提醒等固定摘要的加载、失败和恢复均保持既有行数、行高及导航位置；未知数量使用“—”，加载状态供辅助技术读取，失败提示融入既有行，不增删额外状态行。直接进入与刷新同时核对首帧，不能仅验稳定态。
- 目标容器负责读取反馈，壳层保留写入与会话错误兜底；导航统一接入 Astro 生命周期，120ms 后显示顶部进度，覆盖侧栏、工具栏、条件提交及前后退。保存、删除等写入保留防重复及动作反馈，不叠加同一读取任务的全局动画。请求完成、失败、关闭和切换时均清理状态，旧响应不得覆盖当前对象。
- 尚无内容的异步业务分组在内容确定前保持隐藏，空结果不占边框、留白或高度；有真实内容或读取失败后再显示。加载状态继续由目标容器承担，不先展开空分组制造临时分隔线；核对读取中与完成后的实际位置，避免无内容区域导致阅读跳动。
- Inspector、侧边 Sheet 共用 220ms 进出节奏；退出期间保留定位、内容宽度和选中布局，按实际动画完成收起容器，不能提前移除决定几何的状态。停靠式 Inspector 的轨道宽度与间距一同收拢，覆盖式保持背景尺寸；快速重开从当前画面继续并取消旧退出任务。
- Sheet 与居中 Dialog 的面板、遮罩成对淡入淡出，两者退出完成后才执行原生关闭；移动端详情、抽屉和嵌套确认共用滚动锁，最后一层关闭后恢复原位置，保留滚动条槽位避免背景横移。遵守减少动态效果。
- 站内未保存确认使用 `businessConfirm`，默认聚焦“继续编辑”，“放弃修改”明确执行丢弃；取消保留表单、焦点与滚动。重复触发不叠加对话框；浏览器刷新和关闭页签仍由原生 beforeunload 保护。
- 删除、恢复、定稿、历史影响与共享身份更正同样使用 `businessConfirm`，明确对象、影响和确认动作，默认聚焦取消；站内不再调用浏览器 confirm／alert。失败在所属表单、记录或操作区反馈，保留输入并允许重试。
- 例会定稿先定位未完成字段，再确认冻结；校验失败在底部操作区显示可读错误和处理入口，不静默返回。来源变化引导刷新，已确认隐藏字段不再拦截整表校验；成功打开对应冻结版本，失败保留草稿输入。
- 例会以实际值比较判定修改，不以点击或聚焦置脏；改回原值清除未保存状态。未修改不能建立同阶段新修订，已存草稿的同号定稿、会前转会后保留入口。首次建立修订草稿及每次定稿复用公共确认框，明确目标 V 号与影响，默认“继续编辑”；同版草稿保存不重复弹窗，成功返回总览，失败保留输入。
- 例会卡片共用“标题＋版本＋资料”文字行：固定SVG图形16px、点击区域24px，按文字中线对齐，长标题自然换行；不强撑标题高度或另占分类行。草稿／定稿同组同行等高，只有底部明细对齐；卡片间距12px、历史基准使用轻量文字、观察／行动初始64px，下一步与确认同行。事项问题／方案同为64px文本框，进度与复选／删除操作顶线协调；冻结版本保留纯只读表格。

### 数据界面的层级、空间与对齐

- 嵌套展开的汇总与明细共用父级左右外边界，内距由单元格管理；内部列可按不同语义分配。只由一层容器负责整体宽度及横滚，列的实际最小宽度与断点使用真实可用空间，展开不改变汇总宽度。验收按视图×状态×视口分别记录，平铺五档不能代表分类五档；短标题、多分类与收起／展开对照不能被单个长名称样本替代。

- 本节覆盖表格、矩阵、数据卡片的标题、计数、工具栏、正文及页脚。同语义、同优先级使用一致的字体层级，名称、主要输入与只读主值按既有语义规格选择；不能按局部剩余空间随意缩字。参考 Formward 的内容宽度与实物验收原则，不复制其他产品的字号或布局。
- 宽度与留白依据真实长名称、金额／人数／单位、内边距、选择箭头和点击区域分配。框内文字与只读值按同一阅读边缘比较，长数值完整可见；空值、未知、不适用与零分开。不复盘等不适用任务不显示待录入指标。空间不足采用内部横滚或完整字段组重排，不用裁字、缩字或无依据空洞换取固定列数。
- 阅读记录表先按日期、状态、标题和完整操作组的内容宽度分列；限宽内容连同区块标题和历史入口整体居中，左右表外余量相等，不把所有剩余宽度给标题列。PDF等同组操作保留完整可读宽度；常规单行记录按内容和点击区域确定行高，不能由被挤窄的次要动作制造空白。长标题可在有完整读取入口时截断，真实长备注合理换行；生成中与错误反馈在本单元格内显示，不改变其他列宽。
- 同组统计卡采用明确的主标签与主值锚点；同排标签＋数值组成紧凑内容组后整体居中，辅助说明不得移动主信息或撑开组内间距。排期七项卡片标签12px／18px、数字22px／26px、间距8px，桌面最小64px、手机58px；推广细分由相邻测试／放量卡表达，不重复增加说明行。空间不足按完整卡片横滚，不能缩字或拆开标签与数字。顶部紧凑汇总与上下排列的指标按自身场景保持共同锚点。例会本期摘要依据自身可用宽度从四列切为两列，长金额完整显示，屏幕布局不覆盖打印规格。
- 按钮、筛选、折叠入口等交互控件的数量附注使用半角括号，标签与计数之间保留一个空格，例如“一键保存 (4)”；纯计数括号内无空格，必要单位／含义保留，如“历史版本 (3 版)”。SSR与动态回显一致；普通中文正文、单位及业务备注不套用计数标点规则。
- 操作组由容器统一管理 gap，成员不再叠加外边距。文字、数量与图标作为完整内容组居中；检查实际中线、可见间距和点击高度。`BusinessToolbarActions` 顶栏保留36px／8px间距，区块 `variant="section"` 使用36px、13px／20px文字和12px间距，主要蓝底与轻量次要动作各自一致；表单与 Inspector 仍用40px常规规格。只读汇总插槽不强制改成操作组，手机按整组换行并保留区块动作。
- 同类表格使用同一套列锚点与对齐规则，表头和正文分别声明，不继承浏览器默认对齐。录入型表格的表头在列内水平、垂直居中，名称、单位及必要说明组成完整标题组后整体居中；正文名称／说明左对齐，金额／人数输入右对齐并使用 tabular-nums，短状态与行内动作居中。
- 阅读型表格按内容的阅读与比较关系确定对齐：名称和连续说明左对齐，数字按比较边缘排列，短状态／操作按列居中；表头对应同一列的阅读锚点。同类展示的既有专项规则继续适用，例如非推广日期、帖子信息、轮次和两项比率整组居中，长原因按阅读关系左对齐；不以全局 th 居中覆盖不同类型。
- 推广每日复盘与残留补录共用居中表头，保持既有列宽、输入宽度与局部横滚；Inspector 是字段表单，沿用可见标签布局。上标、角标不参与主文字的居中宽度或行高计算，说明链接作为表头标题组的一部分。
- 以混合状态、长名称、长数字、未知与真实零值验收，等待字体稳定后实际查看桌面及手机图像。实际验收文字或标题组的边界与列中心／阅读锚点、垂直位置及内边距，覆盖长单位、来源说明、窄屏和动态回显；只有单元格样式一致仍可能视觉错位。规则变更须检查全部同类入口、共享接入示例与回归。
- 条件字段与辅助操作按当前任务选择位置，不能将整块表单塞进短单元格、让整行围绕最高内容产生无意义空白。默认、选中、展开、禁用、错误及回显都检查实际字体、字号、控件高度、主控件中线与行高连续性；公共样式层叠可能覆盖局部规格，静态声明与默认截图不代表条件态合格。数据组件变更须运行公共UI与数据条件态专项，逐项标记已验证状态。

## 业务页面：高密度运营台账

- 业务页按区域区分工作与展示：日历操作、表单、审批保持稳定；生命周期、占比、趋势和已登记结果允许主动设计可见动效。沿用清晰分区与高信息密度，不复制首页的 3D 穿越效果。
- 业务页吸收 Apple Design 的界面原则而不是仿制 macOS：桌面端以垂直导航和上下文工具栏组织层级，移动端自适应为紧凑 Bar；按下即反馈，弹层从触发关系中产生并沿原路径关闭。
- 同属“内容发布控制台”的页面必须共享同一应用壳层，不得分别复制并修改 Sidebar、Toolbar 和移动端导航 CSS。新增业务页面应复用统一 Layout / 组件；已有页面出现差异时优先收敛公共壳层，不在单页继续打补丁。同一业务分组的导航项进入同一列表，统一行高与组内间距；组间距仅用于不同分组，不将同级模块作为组外独立项。
- 半透明材质只用于浮动工具栏、弹层等功能性上层，表格和密集数据区保持实色与清晰对比；不以毛玻璃代替信息层级。
- 帖子版本是业务结构，不是装饰编号：V0 表示新做帖，V1 及以后表示从原版本派生的改帖。
- 排期页采用 `Sidebar + Toolbar + Inspector + Sheet` 的工作台结构；桌面端左侧导航保持稳定，主区默认承载月历，显示方式按“月历／台账”排列，默认项在前，并可切换紧凑时间轴台账；选中内容后在右侧检查详情和版本关系。
- 排期与推广状态共用同一份按日分组的紧凑时间轴数据，不建设相互割裂的推广看板；状态带提供本月内容、待发布、推广中、测试中、放量中、尚未登记和已发布视角，其中聚合筛选名为“推广进行中”，测试与放量数量由相邻独立卡显示。
- 台账与月历是同一批数据的两种表达；新增、编辑和改帖统一使用右侧 Sheet，移动端使用全屏形式。
- 台账不设置独立删除列；删除排期移入 Inspector 底部“更多操作”，使用弱化危险文字并在执行前明确提示不可恢复。Inspector 以实发登记为唯一主动作，编辑排期和创建改帖作为同一层级的次级动作。
- “推广周期已结束”“测试淘汰”和“放量淘汰”使用不同文字标签，三者均不进入当前推广状态带。
- 月份标记、表头、状态标签和日期用于编码真实业务信息，不作为装饰编号。
- 延期发布、尚未登记、数据库异常和字段错误必须有明确文字。紧凑月历通过图例、悬停提示、可访问名称和详情保留状态文字，卡片底部不重复展示。
- 表单保留可见标签、键盘焦点和字段级错误；横向信息表格在窄屏可滚动，不压缩到不可读。
- 学科与帖子分类使用相邻的两级选择控件；帖子分类只显示当前学科下的有效选项，切换学科时清除不再匹配的分类。
- 各学科新建或编辑必须选择有效分类，可使用“临时帖”；无法确定学科时使用“临时学科 / 临时帖”，历史空分类归入临时帖。
- 创建改帖只保留“具体改动说明”，输入框下方以简短说明示例提示“改动了哪些部分”以及“改动原因和希望达到的效果”，不增加额外装饰。
- 完成情况在独立实发登记 Sheet 中作为系统计算结果展示，不提供手动状态选项；满应发 2 小时未登记先提醒“尚未登记”，登记后按真实发布时间核对逐日原因；实发登记补齐每一天的责任方与必填文字。历史理由默认折叠，展开查看逐日明细。新做帖、改帖和编辑排期不混入实发字段。
- Inspector 和 Sheet 必须管理初始焦点、Esc 关闭与未保存提醒；移动端 Inspector 和 Sheet 使用全屏形式，控制台已实现入口收纳为底部 Bar。
- 沿用 `Control Night`、`Blueprint`、`Marker Orange` 和 `Monitor Mint`，但把大胆表达留给首页。

### 内容发布控制台统一壳层

年度总周期规划、排期管理、推广帖复盘、非推广复盘、例会总复盘和系统设置属于同一个应用。所有页面使用同一个共享 Sidebar 组件；跨页面切换时，只有主内容和当前导航状态可以变化，外围框架不得跳动或换色。

- 桌面 Sidebar 固定使用同一宽度、背景色、内边距、品牌区高度、导航行高度、圆角、图标尺寸、激活态和底部区域。具体尺寸与色值以当前统一壳层实现为准，可以根据跨页体验继续调整；不得因模块主题单独换色或改变主内容起点。
- 顶部 Toolbar 固定使用同一高度、左右内边距、底色、边框和三列对齐基线。具体高度由跨页面实际信息密度共同确定，可以继续试调；中间筛选或切换控件不得单独把整条 Toolbar 撑高。
- 当前 Toolbar 桌面端固定为 `72px`、移动端固定为 `62px`，横向占满 Sidebar 右侧 Workspace；标题、年月导航、分段切换、汇总和操作按钮均使用共享组件，单页不得覆盖其字体、颜色或几何。
- Toolbar 左侧信息统一为“模块主标题 + 当前上下文”两行结构。主标题的字号、字重、行高一致；第二行只承载年份、月份、视角或截止日期等上下文。`THE PLAN`、`Daily Promotion Review` 等英文可以作为辅助名称，但不能改变标题区高度和基线。
- Toolbar 中部用于当前页面的日期导航、视角切换或阶段切换，右侧用于汇总和主要动作。某页没有对应内容时保留网格对齐，不用改变整体高度补偿。
- Toolbar 中部只允许单行控件。推广每日与历史共用持久化顶栏和固定的“每日复盘 / 历史总览”切换；阶段复盘放入周例会。数据截止时间放在生命周期标题旁，不因切换改变公共控件位置。
- 移动端统一使用同一底部导航高度、背景、图标和安全区规则；Toolbar 的移动端高度、标题折叠方式和主要操作位置也必须一致。
- 页面专项色只进入内容区的数据编码，例如学科色、测试黄和放量绿；不得改变 Sidebar 或 Toolbar 的基础色。
- Sidebar 必须形成完整的样式隔离边界：组件根节点及全部后代统一声明 `box-sizing: border-box`，并由组件显式声明字体族、基础字号和行高。不得让 Sidebar 继承页面级 `* { box-sizing }`、`body` 字体或 `body` 行高；否则 scoped 与 global 页面会把同一导航行计算成不同高度。
- 业务页面只能引用共享 Sidebar 并传入当前激活项，不得声明 `.sidebar`、`.module-nav`、`.sidebar-foot` 等独立侧栏结构或样式。修改 Sidebar 只进入共享组件；右侧 Workspace 的样式不得命中共享侧栏命名空间。
- Sidebar 以“计划与执行 / 复盘与沉淀”表达真实业务分组，导航使用单行中文名称和语义线性图标。当前项保持完整圆角选择面；hover、键盘焦点、按压和加载必须各自可辨，但不得通过图标弹跳、整页淡入或分散动效制造反馈。
- 跨页面切换时 Sidebar 持续存在，点击先更新当前项；只有等待超过短暂阈值才在 Toolbar 下缘显示单一加载条。预取只由 hover、键盘 focus 或触摸按下触发单个目标，不在页面打开时请求全部模块。
- 验收业务页时必须连续点击所有控制台模块，检查 Sidebar、Toolbar、主内容左边界和首屏垂直起点是否逐页保持不动。单独截图看似合理但跨页跳动，仍视为不合格。

壳层参数属于实现细节，不作为永久设计结论；长期结论是同一控制台的所有页面必须使用相同参数和信息结构。发现跨页差异时应通过共享壳层一次性消除，不把某次试调值继续复制到新页面。

控制台页面结构统一由 `BusinessConsoleFrame`、`BusinessConsoleToolbar`、`BusinessPageHeader` 和 `BusinessSectionHeader` 组合。页面级标题使用清晰的中文工作对象，不增加装饰性英文眉题；说明和右侧元信息仅在确有必要时提供，省略时不生成占位或空行。紧凑台账页可以直接从工具栏进入内容，不强制增加页面级标题。

- 页面标题只说明当前工作对象与必要边界，不重复操作顺序、到期规则或显而易见的步骤。
- 区块标题使用共享 Section Header；标题、说明和右侧计数的字号与间距不得由单页重新定义。
- 相同层级的 Bar 使用共享 Toolbar；页面只通过命名插槽提供日期导航、视角切换、汇总和主要动作。
- 新业务页面优先组合上述组件。只有信息结构确实不同且无法通过组件 Props 或插槽表达时，才新增视觉结构。

已确认设计具有继承性：新增功能优先融入现有核心结构，不能因增加数据或操作而自行替换。全局同步负责跨页一致，设计继承负责保留已确认成果；必要替换先说明原因并取得确认。

### Daily Promotion Review

- 未开始、首次待定与可填指标共用每日主表表头和列锚点。日期、名称／版本、资料及真实状态可读，五项指标灰底禁用、成本为“—”，不作为零事实或待复盘计数。已开始后的暂停／测试结束待定仍按真实指标规则填写。
- 尚未开始在状态下“设置安排”，待定为“修改”，使用原位锚定浮层及公共未保存确认；截止日选填，修改原因必填。初次安排前右侧提示先设置当日，待定后右侧次日安排与行末“保存／取消”独立操作，不参与一键指标保存；有未保存安排时先处理该草稿。无截止日每日推导昨日一行，不积累历史灰行；有限待定仍锚定昨日与截止日较早者，到期次日才处理下一步。保持 T+1、指标输入宽度、内部横滚及其他草稿节点。
- 首次待定的次日下拉保留原生控件；继续待定不自动弹窗、无截止可直接保存。安排列共用192px最小宽度，继续待定时由128px下拉、8px间距和56px截止日辅助入口组成；日期放在锚定气泡，关闭保留同一行草稿，不新增第二个保存。行末动作列共用112px，保存56px、取消48px、间距8px，均高40px；条件选择不抬高行，指标最小宽度及局部横滚保留。

- 第八版参考为正式布局基准：中性浅灰 `#F6F7F9` 背景、白面板、`#E5E7EB` 细边框、10px 圆角。侧栏和蓝色主色保留；主内容居中，面板最大 1440px、桌面两侧至少 24px。
- 只有“推广生命周期”“每日复盘”两个一级面板，概览在上、待办在下，间距 24px。概览一帖一行约 64px，桌面五行连标题不超过 400px。名称／版本、真实阶段轨迹、累计三指标、当前状态、详情共用稳定列，长名称不推动其他列。
- 阶段轨迹仅表达真实事件和日期：开始测试、测试暂停、测试结束待定、开始放量、放量暂停及终态；直接放量不补测试，不生成目标周期或完成率。测试黄、放量绿、暂停灰集中在节点和小面积日期标记。无复盘用中性文字，独立于真实阶段。
- 总消耗、实际开口成本、实际留资成本由服务端同一事实口径计算；成本为累计消耗／累计实际人数，不平均每日成本；无事实或零分母显示“—”。只使用已保存事实，不随输入草稿变化。长金额不得覆盖相邻列。
- 概览与历史复用同一组件；“查看详情”在当前行下展开每日表及表尾汇总，默认收起，名称进入共享 Inspector。历史已结束分区和日视角日期继续默认收起。
- 真正进入且可见后，节点和连线按顺序在约 600ms 内呈现，当前节点强调一次；真实新增事件局部强调约 300ms。填写、筛选、详情和局部保存不重播整个历程；Observer 回调复核当前页面与请求代次。减少动态效果直接显示最终状态。详情与分类明细使用成对 220ms 展开／收起。
- 提交立即防重复，成功时按钮短暂显示“已完成”与成功色，再原位更新队列和待填写数量；常规反馈约 320ms，减少动态效果时直接更新。草稿成本随输入直接呈现，不滚动数字或补间；静止页面不循环闪动。
- 每日复盘直接单行填写，列序为日期色块、内容／版本、居中当日状态、消耗、平台开口、实际开口、平台留资、实际留资、两项只读成本、次日安排、完成复盘。名称列按实际 MiSans 测量，短名称约 112px、最大 176px，不吸收宽屏余量；所有行与表头共用锚点。
- 输入常规高 40px，消耗至少 96px、人数至少 80px，数值右对齐且使用 tabular-nums。日期色块水平、垂直居中；状态名称与下方“修改”在同一列分别居中，与内容、消耗之间保留稳定间距。金额单位元、人数单位人只在表头标明，不再重复“投入／消耗”标签。成本使用浅灰只读文字组，紧接五项输入、位于次日安排之前，不伪装输入框。窄屏保持整行语义，在局部表格内横向查看，日期随行移动以免覆盖内容，不造成整页溢出。
- “完成复盘”放在行末、紧接次日安排，使用蓝色主按钮、轻渐变、细边框与浅阴影形成可按压感；不增加面板装饰或扩大阴影。“修改”保留低强调文字操作，计算结果保持只读层级。
- “修改当日状态”用锚定气泡，不增加行、没有日期选择器；展示原状态、合法后继、必填跟进原因、变更预览及保存回执。保存前保留原状态，取消只丢状态草稿，Esc／关闭保留草稿与焦点。保存后保留“修改”入口，误选终态也可重新更正：基于该日覆盖前状态重选或恢复原状态，刷新后仍可操作。保存保留数字和仍合法的次日选择；终态无需后续动作，恢复进行中状态时恢复相应次日选择。
- 气泡跟随当前状态入口定位，靠近视口边缘时避让，不挤动表格或新增一行；保存回执、再次修改和关闭焦点仍留在原行入口。
- 修改状态固定作用于该行数据日期；次日安排从数据日期下一天生效。后继规则由共享业务状态机提供，实际修改排除当前状态，“继续”只存在于次日安排；测试结束待定的正常状态推进不提供恢复测试，同日误选的撤回按上述更正规则处理。
- 每帖按最早未完成日处理；待填写仅计当前允许录入的指标。今天待开放默认收起，按共同开放时间分组、约 48px 一条；前日未完成单独分组，不重复铺大卡片。没有可填数据时空态与最早开放提示保持紧凑。首次推广前的安排并入主表灰行，不计指标待填数。
- 暂停／待定持续至主动变更，启用后的每个业务日仍需复盘。仅新草稿五项默认零，用户可直接选择次日安排并保存；已有草稿和实际输入优先，不因刷新或切换状态覆盖为零。非零跑量继续填写并计原阶段效果，暂停日期不计正常投放天数。
- 缺少首次笔记 ID 时在行旁小气泡补齐，与指标共用草稿和原子提交；不自动展开完整 Inspector。按活动＋日期合并全部相关队列、分组与计数，保存和跨午夜保留其他记录节点、输入、焦点及滚动。
- 补录按笔记 ID 搜索并明确选择已测试淘汰的活动、版本和日期，新增固定“淘汰后残留”行；五项指标、只读成本、完成补录，无次日安排，不恢复推广或改变结束日。阶段复盘追加数据标明原阶段及实际数据区间，已保存快照不改写。
- 推广历史与排期继续复用业务历史、权限和影响确认；真实事件显示更正前后与原因，技术审计保留于底层。已有指标的历史状态及下一步修改由管理员操作，破坏性冲突先展示日期和数量再确认。

### 非推广复盘表格

- “历史数据总览”及分类明细一行对应“帖子 × 轮次”，共用实验日期、帖子、轮次、点击率、3 秒阅读率和紧凑操作列。实验日期原列同行显示完整的上海实际发布日期与应复盘日期，以“至”连接；首轮结束于发布日加7天，二轮结束于发布日加15天，不以录入日或人工数据截止日替代，排序仍按发布日期。“分类均值查看”使用分类、轮次、样本、点击率、3 秒阅读率、明细六列单层表头；同一分类两轮上下排列，分类信息只出现一次，点击直接在下方展开明细，可同时展开多类；不提供轮次筛选。公共工具栏、表格外框和真实记录节点不随模式重建。
- 帖子名称是行内主视觉锚点；行、标题和末列动作统一打开该排期与轮次的 Inspector。待复盘动作名为“点击录入”，已复盘和不复盘名为“查看详情”；帖子名称和版本在上、学科分类在下组成居中信息组；长分类在本列换行。桌面动作居中，手机位于内容组底部，日期区间保留单行。文档不独立占主表列，笔记 ID 在悬停与 Inspector 中提供完整值。
- 点击率和 3 秒阅读率以受内容约束的相等列宽在表格中部整组居中，轮次与指标组保留明确距离，实际主值桌面 20px、手机 18px，使用 tabular-nums；主值下方13px 的 pp 差值与 12px 的同类均值、样本量构成辅助层级。手机将帖子信息置于上方、两项结果并排，避免横向寻找核心数据；轮次由节点列明确表达，悬停保留该轮完整说明。正向、中性、负向仅改变差值文字颜色，不使用整格高饱和背景。
- 节点只显示紧凑的“首轮 / 二轮”中性标签，不重复页面视角已经表达的完成状态。桌面端整行点击或键盘打开右侧 Inspector，移动端 Inspector 占满屏幕并支持 Esc 关闭与清晰焦点。

- 不复盘列表按日期、帖子、轮次、不复盘原因及查看详情组织，移除两项指标表头与待录入／同类基准；原因自然换行，详情保留恢复及既有历史。

### 非推广阶段复盘

- 主内容使用高密度数据表，一行对应“帖子 × 复盘节点”；低价值列压缩，帖子名称和点击率、3 秒阅读率获得主要宽度，笔记 ID 不独立占列。
- 点击率和 3 秒阅读率并列同权展示。主值使用深色等宽数字，与 pp 差值同一行；正向、中性、负向仅使用低饱和绿、灰、红差值文字，同类均值和样本量另行显示，轮次由节点列明示。
- 分类默认规则属于全局设置，只从 Sidebar 主导航末尾“系统管理”分组的“系统设置”进入，不出现在复盘工作流中；推广转非推广仍使用原因输入和明确影响说明。
- Inspector 在固定身份头部下默认展开紧凑资料区，提供项目文档、小红书帖子、应发时间、实际发布时间、排期详情和完整笔记 ID／复制；资料区下接复盘表单。资料缺失显示“未登记”，不制造空链接。文档、帖子及排期详情用新标签打开，保留当前输入；排期深链接按应发时间的上海月份与排期 ID 定位。
- 主表节点只使用紧凑的“首轮 / 二轮”中性标签，不重复页面视角已经表达的完成状态。右侧 Inspector 的数据截至、点击率和 3 秒阅读率保持同一录入结构；窄屏再自然重排。
- 例会非推广使用卡片，二轮携首轮对照；本期主体与首轮对照身份分开。指标、结论、日期与不复盘原因只读引用原复盘入口，准备区提供缺项跳转；笔记 ID 默认可见并只读，独立实时读取且不进入冻结材料；来源明细气泡入口保留。候选区仅勾选推广帖，表下明确非推广全量处理规则及待处理数；非推广已填与待填共用同一网格。非推广头部按内容自然增高，显示版本、7／15天轮次、处理状态与实际发布日期；推广与非推广共用紧跟标题文字的轻量ⓘ资料入口，复用同一气泡控制器，悬停／聚焦预览、点击保持、Esc／外点关闭，提供项目文档与小红书链接，缺失显示未登记。资料开关不改变卡片、滚动或输入。

- 非推广筛选使用相邻的学科与帖子分类控件；切换学科清除不匹配分类，视图与 Inspector 切换保留筛选。跳过及恢复在 Inspector 独立表单操作，原因必填，不受指标输入要求影响。
- 排期待办提醒位于共享侧栏顶部，优先显示“尚未登记 N 篇”，手机在排期导航显示数量；未登记不直接视为漏发，不重复计入待补原因。改期审批与逐日理由沿用 Inspector，历史明细和已处理审批默认折叠。

### 年度总周期规划

- `THE PLAN` 默认在一个页面纵向展示总规划和所有学科细致规划，使用冻结的分区、SOP/帖集和规划项目列以及 1—12 月年度矩阵。
- 总规划使用独立只读汇总带，与可编辑细致规划建立明确上下层级；桌面端在 1280px 及以上应同时看清完整 12 个月。
- 总规划与细致规划共享同一组固定业务列和 12 个月份轨道：总规划的科目跨越规划分区与 SOP 两列，周期对应规划项目列；横向滚动、分区筛选和停用状态切换不得改变月份起点。
- 1、4、7、10 月使用更明确的季度起点分隔；季度节奏只帮助读取年度，不新增业务状态。
- 规划分区、SOP 和规划项目列按顺序冻结；SOP 只承担箭头入口，规划项目承担名称和版本状态。sticky 层级依次为月份内容、固定数据列、月份表头和交叉表头，不允许相互透底或覆盖。
- 时间块按半月起止；保留 12 个月表头，月份内部使用低存在感的月中分隔。矩阵条幅直接显示用户填写的备注，长备注最多两行并在 Inspector 完整呈现，不显示乘法、加法或问号。
- 科目使用稳定色相：TMUA 蓝、STEP 紫、面试课橙；深色表示付费推广，浅色表示非推广、观察或自然流，同时提供文字图例。付费状态不由数量或分类强制决定。
- 同一周期保持一条连续条幅，付费子区间与自然流子区间分段着色；混合条幅使用清晰的备注文字层，不能因背景深浅影响文字可读性。总规划、主矩阵和缩略轨道共享半月比例与色彩含义。
- 桌面端和移动端都允许年度矩阵横向滚动，不把 12 列压缩到不可读；窄屏编辑器使用全屏或重排布局。
- 规划详情沿用 Inspector，新建与编辑沿用 Sheet/Dialog；选中规划时固定业务列和月份轨道形成连续整行反馈。
- Inspector 按“规划身份 → 当前状态 → 年度缩略轨道 → 时间块 → SOP → 备注 → 版本历史”组织，并与主矩阵共享月份比例和学科色。版本历史沿用工作台正文、辅助信息和中性次级按钮，日期使用北京时间 `YYYY-MM-DD HH:mm`；动态加载的历史和版本内容保持相同字体层级。
- Inspector 时间块显示阶段名称、半月范围、完整备注及分段推广状态；窄屏允许自然换行，不用失衡的固定列挤压中文内容。
- 年度矩阵的规划项目列将名称、版本号和停用状态放在同一行；分类关系在 Inspector 中查看，不在矩阵中重复形成第二行。
- 分区、SOP 和规划项目列保持紧凑；SOP 使用可访问的箭头链接。时间块编辑按半月范围、自由备注、推广安排和可选阶段说明组织，提供即时预览；年度复制使用轻量 Dialog。

## 首页概念：浅弧封面带与连续工作流

首页沿用已确认 A 的纵向推进与紧凑后两区，以九张真实封面形成浅弧电影带。

- 初态中央 2–3 张清晰，两侧沿同一浅弧缩小、渐隐；所有封面使用统一相位，不各自漂浮。
- 初始完全停留约 2.6 秒，再以 1.15 秒柔和推进一张；下滑时同一条封面带逐渐展开，平铺后继续低速匀速横向循环，约每 4.5 秒移动一张的位置。
- 每张图只有一个实例，换位发生在场景外；平带两端保留窄渐隐，不暴露回收瞬移。
- 封面、目标文案和底部轨道各自保留净距，不用覆盖文字的局部遮罩补救拥挤。
- 六条轨道表达策划、内容、视觉、发布、用户触点和复盘如何依次衔接并持续回流。
- Hero 在同一画面内并列呈现“工作平台是什么”和“内容为了什么”：左侧为工作台定位，右侧以 `WHY WE EXIST` 标记使命句，下方用箭头连接点击、读完与咨询目标；不再设置独立的使命区块。
- Hero 的信息层级以主标题为第一焦点，使命为第二焦点，行动路径和流程轨道作为辅助层；避免标题、使命、目标和轨道同时使用最高对比度。
- 01–06 仅由纵向滚动推进，自动播放不改变当前流程环节；环境使用稳定深蓝，避免与封面同时变化分散焦点。
- Hero 结束后由浅蓝灰工作流区按正常文档流承接深色场景，系统入口保持明亮列表结构；第二页不得使用负边距、顶部圆角或向上阴影覆盖 Hero 内容。
- 工作流采用侧标题＋3×2 六阶段，系统入口采用同一内容轴上的三行列表，降低后两区留白与滑动成本。
- 大胆程度集中在首屏，离开可视区后停止封面播放。

## 必须保留的内容宗旨

- 让用户愿意点击；
- 让用户愿意读，且愿意读完；
- 让用户愿意进一步了解与咨询。

宗旨必须使用网页文字呈现，不写入生成图片，保证准确、清晰和可访问。

## 首页视觉变量

- `Control Night #0B1B2B`：Hero 基础空间与页脚；
- `Signal White #F5F7F4`：页面底色和主要文字；
- `Blueprint #5B8CFF`：Hero 环境光、轨道和结构信息；
- `Marker Coral #FF8A68`：当前流程环节和关键动作；
- `Monitor Mint #9ED8C4`：触点环境光和少量辅助状态；
- `Workflow Mist #E9EFF2`：Hero 后工作流阅读区。

首页标题使用紧凑、强重量、较窄的无衬线表达；正文使用适合中文连续阅读的中性无衬线；编号按需使用等宽字体。工作台使用前述自托管 MiSans 与中文、日期、数字层级，不将中文状态改成等宽字体。首页正式品牌字体后续单独确认，不影响已确认的工作台字体。

## 帖子封面

- 正式素材优先使用真实小红书帖子封面。
- 推荐比例为 3:4；组件也以 `aspect-ratio: 3 / 4` 约束。
- 素材应先移除不应公开的信息，不编造业务结果或用户数据。
- 当前使用九张用户确认的真实封面，以 `object-fit: contain` 完整展示；每张素材只创建一个循环实例，避免同屏重复。
- 代码生成的封面板只作为图片未配置时的备用显示；替换素材不应重写动画。
- 浅弧的尺寸、角度与透明度由距中央的位置连续计算；纵向展开插值构图，横向运动始终沿用同一相位。

## 动效与性能

- 滚轮继续控制正常页面进度，不锁定滚动，不制造强制翻页。
- 使用现有 React Island 和 CSS transform／opacity，不引入大型 3D 库；SSR 输出与动画首帧一致的构图。
- 暂停／播放入口在浅弧和平带均可键盘操作，暂停冻结横向播放，正常纵向滚动仍可展开构图。
- 流程轨道到达 06 后，封面仍在 Hero 离场过程中继续循环；首屏离开可视区或标签页隐藏时暂停，恢复不补播隐藏时间。
- 支持 `prefers-reduced-motion`；减少动态效果时保留静态浅弧，不持续推进封面，并取消额外的 Hero 滚动占位。
- 场景按内容容器宽度和首屏实际高度计算，维持已确认桌面构图与净距；后两区继续按正常文档流承接。

## 登录与账号反馈

- 保留总枢纽首页视觉，仅增加清晰的登录入口；独立登录页使用现有深蓝、浅蓝灰、系统中文字体和安静表单，不复制 Formward 品牌或人物场景。
- 桌面账号菜单位于共享侧栏底部，手机位于固定高度的工具栏内；菜单使用原生 popover，避免被工具栏或 Inspector 裁切。
- 管理入口随服务端角色显示；年度与排期动作按服务端有效操作权限呈现，员工默认年度只读，关闭的操作不显示为可点击动作。
- 写入按钮立即显示忙碌并防重复提交；写入的共享兜底提示在等待超过 200ms 后出现，并发操作独立计数。读取使用上方 500ms 目标区域反馈，不套用写入计时。失败保留输入，会话过期提供新标签页重新登录入口；退出以完整导航清除上一账号页面状态。

### 待定区间、阶段快照与例会

- 首次安排按业务日期显示，三种首次状态为尚未开始、开始测试、直接放量；首次待定的下一步保持空选项，无截止日按昨日推导一条灰行。末日未安排时只保留这一行，不自动延长截止日或累计未来逐日待办。已开始活动的测试暂停、测试结束待定与放量暂停使用上方 Daily Promotion Review 的逐日规则；单独修改状态不要求先提交 ID 或指标，完成每日复盘仍遵循首次 ID 与五项指标校验。
- 推广历史和排期 Inspector 共用状态编辑器；保存仅刷新本篇业务行与摘要，保留其他帖子草稿、公共表头、工具栏、滚动与选择。历史影响用公共异步确认框列出冲突日期与数量，原始指标可从审计查看。
- 排期待审沿用排期台账的容器、日期分组、版本与状态样式，每条申请独立一行；详情使用共享 Inspector，默认展开首项。原内容与申请内容按字段纵向对照，完整日期与理由无需横向拖动，固定底部提供通过／驳回。设置常规导航仅含业务规则与账号权限，排期审批从排期管理进入。
- 推广每日／历史共用顶栏，手机底栏只占一个推广入口；新增阶段复盘在周例会中呈现。旧阶段快照保留只读版本与来源明细，不再提供新建／重新生成按钮。
- 例会总览采用紧凑会议列表，白底区块沿公共正文边界组织，标题、记录及历史内距一致；不再限宽居中或使用六列分散信息。名称15px／500与版本同行，轻量状态就近呈现；会议时间与类型、完整复盘区间、中文周期在下方分组，辅助信息12px／18px。记录上下16px、左右20px，手机左右12px；空间不足按完整组换行，动作移到下方，列表不横滚。查看PDF／下载直接可用，重新生成／上传收进“更多”公共点击气泡；附件按需出现，反馈只影响所属记录。主行首部与36px紧凑动作同中线，手机操作至少44px，长名称可自然增高。修订草稿与定稿并存须区分标题将打开的版本及PDF所属版本。历史沿用整体／逐会议默认折叠，内含紧凑版本项与完整备注；初始草稿删除及会前讨论入口保留。进入会议后隐藏总览，顶部仅显示一次会议名称和草稿／版本状态，右侧返回总览，底部仅一处保存与定稿。准备区确认候选并补齐来源后进入正文，填写推广卡片、结论和事项；非推广只读。常规桌面卡片三列铺满，≤1100px 两列以保证金额和输入宽度；同类型、同一行卡片等高，不跨推广／非推广区域或行统一测高；正文紧凑排列，底部明细入口对齐。名称／版本与状态、消耗和人数、开口成本／留资成本／点击率、本帖历史、历史同类、观察／行动、次日状态、确认／修改、明细入口按顺序组织。草稿观察／行动初始高度统一为 64px。明细使用原位按钮和非模态气泡，默认下方 8px，底部空间不足时向上避让，最大高 360px；Esc／外点关闭，开关不改变卡片、输入或滚动位置。冻结卡片共用。无本帖历史仅一行折叠，历史同类成本不显示差值、同期与天数。事项为纯表格。
- 候选默认不勾选，“全选推广帖”不包含往期补充。筛选只隐藏候选，保留卡片、输入和勾选节点；刷新保留人工文字和有效勾选，不在文字编辑时重播展示动效。来源慢读复用 500ms 目标反馈，失败保留输入；提交立即防重，成功保留回执。草稿保留填写顺序；定稿按本期结果、核心结论与下一步、推广／非推广卡片、补充分析与事项组织，排期核对用紧凑链接。指标使用本期已满足复盘资格来源的实际跑量口径，核心结论前置；只读卡片取消标题占位、指标突出、同类基准简化为辅助文字，长观察／行动完整且顶部对齐；同一行等高、底部明细对齐。会前标记“拟议安排 · 尚未生效”，会后“已定安排”及快照生效日；不按查看日期计算。会前动作中性、会后主动作蓝色；保存草稿返回表格。只有例会决定的次日安排复用当日状态的居中两行样式：状态在上、蓝色修改在下，字号、字重与间距一致；非例会安排保留原下拉框、选项和操作方式。两列按各自状态共用文字色：测试沿用测试色，放量绿，待定／暂停／结束灰，淘汰红，不继承另一列状态的颜色。例会固定值的状态文字右上角显示不占位的小星号；来源集中在“次日安排（*指例会决定）”表头并整组居中，例会决定默认蓝色下划线、新标签进入例会总览，链接不得置于 aria-hidden 或可聚焦的裁切标签中。修改使用锚定气泡，理由必填；草稿留在原行，保存原位反馈并保留指标、节点与滚动。关闭、切换及导航沿用公共未保存确认，安排草稿未处理时先处理更正再完成复盘或批量保存。窄屏表格内部横滚，日期随行移动以免覆盖安排文字，保留指标输入的最小可读宽度。
- 每日名称／版本旁的 ID 小提示不新增列；悬停完整值，键盘和手机点击查看。首次补填使用锚定气泡，仅 ID、确认、取消与本地校验，不展开整套 Inspector；确认后随复盘保存。测试结束待定的新行默认“继续待定”；一键保存位于每日面板操作区，使用蓝色常规动作，与补录及历史链接保留明确间距。

### 共享正文与 Inspector

- 正文统一使用 `business-console-content` 和 Frame 中的留白变量；页面不得重新声明 `main` 的尺寸、边距或内边距。不同业务表格可有不同结构，公共标题和操作基线保持一致。
- 先检查现有组件和[真实接入示例](code-study.md#共享界面接入)，再实现前端。相邻视图更换内容和选中态，保留共同的工具栏、切换按钮节点；公共坐标与尺寸误差不得超过 1 CSS px。
- 排期、年度规划、非推广与推广历史共用 `BusinessInspector` 和 `business-inspector.ts`；页面只负责业务内容、字段校验和保存，不重写开关动画、键盘或焦点流程。
- 打开详情立即使用页面已加载数据，补充请求仅在面板内显示加载、失败和重试。打开、快速切换和关闭不发起文档导航，不重建左侧列表；保持筛选、排序及滚动位置，异步结果必须检查当前选择，旧响应不能覆盖新选择。
- 桌面详情使用共同宽度、工具栏下方位置和过渡；中等屏宽采用右侧覆盖，手机占用顶部工具栏与底部导航之间的整个工作区。年度矩阵可采用同款覆盖式面板。
- 申请差异由 `BusinessChangeDiff` 与 `business-change-diff.ts` 共用字段结构和样式，每个字段纵向列原内容、申请修改为；主台账的表格宽度与移动端样式限定在列表容器，不得影响详情。
- 应用壳层横向裁切不得创建多余滚动祖先；使用 clip 保留工具栏吸顶。滚动到列表下方再打开覆盖式 Inspector 时，顶部工具栏仍停在原位，关闭后恢复列表滚动与焦点；静态验收截图等待公共开关动效结束，动效另用真实录像与逐帧记录核对。
- Inspector 采用保留当前对象名称的固定头部、单一滚动正文和固定底部操作区，容器整体不滚动；正文使用 overscroll containment，历史及表单自然展开，不建立第二条纵向滚动轨道。手机覆盖时锁定背景，关闭恢复位置。排期按帖子摘要、待处理、相关资料、历史组织；待填原因最早一天默认展开，其余折叠，已填与历史独立收纳，删除进入“更多操作”。
- 打开后焦点进入面板，关闭回到触发行；Esc 关闭最上层详情，业务对话框打开时优先处理对话框。手机限制 Tab 在面板内循环；减少动态效果时取消过渡。
- 未保存的编辑在切换记录、关闭、后退或离开时确认；取消后保留输入和当前记录。深链接、刷新和浏览器前进后退都能还原选择。请求失败保留输入，保存后明确反馈；已复盘更正通过认证 GET 刷新列表和同轮基准。

### 非推广已复盘的轮次与分组

- 表格布局与“分类均值查看 / 历史数据总览”的展示方式统一遵循上方“非推广复盘表格”；此处补充轮次与统计口径。待复盘的业务节点、日期、录入、跳过和恢复流程沿用既有口径。
- 分类按学科与帖子类型聚合，明细保留实发排期（内容版本）和轮次身份，不能因同名合并；默认按实发实验日期倒序。
- 两轮分别使用全部历史中同学科、同分类、同轮次的样本，包含当前帖；筛选和分组不改变样本池。差值是当前指标减去该轮均值，单位为 pp，不能跨轮比较。
- 分类明细与历史数据总览均支持日期及指标排序，复用同一批事实行；排序不改动同类样本池。切换保留筛选、排序、分类展开与 Inspector 草稿；没有数据的轮次显示“—”，不生成事实行或编辑入口。

### 发布登记与月历

- 排期管理默认月历；当月内容、待发和已发筛选保留当前显示方式，跨月待办及推广阶段明细使用台账。月历实际应用筛选，并沿用公共工具栏和 Inspector，切换不改变公共位置。
- 月历卡片底色表达发布状态：按时已发为绿（#DDF2E8 / #205D48）、延期已发为红（#F9E3DF / #913C35）、超时尚未登记为黄（#FFF1BF / #73551D）、正常待发为浅蓝（#E8F0FA / #345679）。推广身份用独立蓝标签（#E0E9FF / #244B9A），非推广为中性灰；状态文字由图例、悬停提示、可访问名称和详情提供。阶段颜色仅用于阶段标签，不覆盖发布底色。
- 月历按应发日期排列。日期按钮和当天空白区域打开共用新做帖 Sheet，预填所选日期、时分留待选择；点击帖子只开详情。日期与时分控件共用同一表单和提交契约，其他新建入口也使用同一组控件。
- 桌面为七列月份网格，手机按同月日期纵向排列。卡片固定两行：推广身份与时间、版本与标题；移除底部重复状态行。标题在桌面、手机及 Inspector 打开后都单行省略，全文由悬停和详情查看。内边距 6px、内部间距 3px、同日卡片间距 4px，桌面日格最小高度 104px，多帖自然增高；键盘提供带日期名称的新建入口。
- 发布 Sheet 包含发布时间、帖子链接或分享文案、项目文档；未来时间直接登记。帖子输入可粘贴完整文案，原始输入保留，旁边预览识别链接；失败与未保存关闭均保留现有保护。
- 首次登记且排期要求同步朋友圈时，在正文末尾、固定操作区上方显示“朋友圈同步确认”组；两个原生复选框分别为“已发送朋友圈／已发送对应需求”，默认未选、全部必选。复用现有18px复选框及14px正文，组内统一间距，窄屏按完整选项换行；错误在组内显示并定位首个未选项，不另弹确认框。切帖或重新开启登记才初始化，其他字段输入与失败不清空；既有登记和不适用记录隐藏且禁用该组，不产生空留白。
- 已有发布时间默认只读，管理员勾选更正后开放时间和必填原因。旧记录精确秒数保持不变。允许留空的历史帖子链接区域直接为空，不显示缺失、补链、豁免或初始化说明，也不显示必填标记。
- 旧预约历史只读并默认折叠；不提供预约模式、审核、到点确认和对应通知入口。延期理由沿用 Inspector，仅列最新排期及真实日期，不展示改期前延期历史；排期申请在排期管理的“排期待审”查看并处理，系统设置不重复放入口。既有设置审核地址仅保留兼容访问。

### 复盘信息与浏览连续性

- 待完成复盘的行布局、字号、日期色块与状态修改位置遵循上方 Daily Promotion Review；帖子身份、数据日期与实际状态清晰区分，版本／学科、笔记 ID 保持辅助层级。
- 每日待办与推广安排名称保持普通标题，名称／版本旁共用轻量资料入口；版本行图形按文字中线对齐，间距只由父级统一控制，扩展点击热区不得撑高行框或叠加可见空隙。入口呈现当前版本项目文档、该排期小红书帖子链接与帖子主体笔记 ID。复用例会原生资料气泡的视觉、悬停／聚焦、点击保持、Esc／外点关闭和视口避让；开关不导航、不创建指标表单或改变草稿／列表位置。已有 ID 完整只读显示并可复制，缺失才开放补填，确认后随本行复盘原子保存；资料查看不成为已有 ID 的更正入口。每日不再建立重复录入 Inspector，历史与排期仍按其独立业务任务使用公共 Inspector。
- 非推广分类明细在本类下方展开，收起后仍停留原位置；明细与历史数据总览使用同一事实行、表头和列宽，原同类基准口径不变。常规分类名称保持单行，完整名称须可读取。
- 阶段节点动效和展开过渡遵循上方 Daily Promotion Review 规范，保持文字、数值及容器几何稳定，支持打断和减少动态效果。时长与错开量是本项目实现参数，不作为 Apple 的规范数值。
- 日期可见性与编辑权限分开：可填写日直接单行录入，待开放预览默认收起，不计入待填写数。开放文案写明次日上海时间 00:00，不能用点击时间顺延业务日；首次推广前待定安排与活动内暂停／待定逐日指标分开，零值草稿初始化和保存规则遵循上方 Daily Promotion Review，不补造历史零事实。

- 规划行的学科、分类新增动作紧跟字段标题，展开区置于对应选择下方，沿用共享按钮和40px表单控件；成功自动选中，失败保留名称与规划输入，取消只收起展开区。系统设置默认账号权限，不再展示业务规则或版本历史。
- 推广复测沿用现有生命周期节点和详情，标注测试轮次及日期；各轮统计在原详情区紧凑呈现，例会按轮使用独立卡片和人工输入。已结束轮次不重复提供当前轮次的下一步控件；会前拟议、会后已定仍按冻结日期展示。

### 例会展示与会中讨论

- 保留结果、结论与行动、帖子卡片、补充分析与事项的阅读顺序。总览以名称为主入口、时间集中辅助、读取操作直接可用；历史入口独立留24px间距，整体及各会议历史默认关闭。列表不套用表格的列宽与全列居中规则。
- 初始 V0、修订草稿、会前和会后共用同一展示正文：本期结果与核心结论／下一步、推广、非推广、补充分析与事项。材料刷新和候选仅作为初始草稿辅助工具。编辑保留构图，正文就地编辑；事项统一使用等高文本框，表头居中、长文字左对齐，进度、勾选和删除居中，按真实控件中线检查。底部唯一保存草稿与本版定稿按钮，草稿保存返回总览，定稿后打开本版只读页。
- 百分比与带符号pp差值共用同一基线；正差为绿、负差为红、零差为中性灰，保留加减号。窄卡片按整组重排，不能压缩字号或把差值拆到下一行。每卡一处同类样本数；成本比较不加差值。无样本用紧凑文字，旧版本仅从已冻结样本补展示。会后空观察和行动合并一行，正文完整换行。
- 版本菜单收纳历史，PDF操作仅在总览末列与折叠历史。A4报告使用嵌入中文字体、可搜索正文、黑白可辨层级、版本与页码；不将网页截图充作PDF。

### 例会阅读、修订与打印

会议页默认阅读，公共只读／编辑切换置于版本栏右侧，PDF操作集中总览。最新版本的编辑保留展示结构，文字原位编辑，指标不变成输入框；历史只读，回溯为单独高风险动作并列明影响。过期安排显示锁定值与短提示，不以禁用整页代替字段权限。

率旁使用带符号的两位小数pp，同一张卡片只写一处同类样本数；不重复展示均值或用长句解释加减。新旧定稿共用此规则，基准来自各自冻结材料。

打印复用同一展示组件与共享视觉变量，A4横向三列，保留中文字体、指标层级、边框和轻底色；移除导航、切换、资料与明细操作。允许适量收紧打印间距，普通卡片整卡分页，长卡片完整跨页，避免首页无效留白与表格截断。浏览器打印和自动PDF均需实际逐页查看。

### 协作、例会准备与查帖

- 工作台助手是全站固定入口，桌面置于左侧账号上方，整行至少64px高；名称14px、辅助信息12px，图标、底色、圆角和焦点沿用工作台变量。点击打开并标出展开状态，不用悬停自动打开。短窗口仅导航区滚动，助手与账号仍可达；手机在已有账号菜单内以至少44px的行进入，不新增底部导航或正文悬浮入口。
