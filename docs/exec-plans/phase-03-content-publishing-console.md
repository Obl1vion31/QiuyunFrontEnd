# Phase 03：内容发布控制台与帖子版本化

## 当前实施范围

- 将运营排期调整为“新做帖 V0”和“从原版本发起改帖 V1+”两条工作流。
- 帖子、内容版本与发布排期分别保存；改帖保留来源版本和原始数据。
- 现有历史排期全部作为互不关联的 V0 迁移，不猜测历史版本链。
- 保留推广状态、应发/实发时间、12 小时延期规则、月度台账、月历和推广视图。
- 业务界面参考 `emilkowalski/skills` 的 `apple-design` 原则：清晰的 Bar 层级、即时反馈、空间一致性、克制材质和可访问性；不安装运行时 UI 库，不把毛玻璃作为唯一风格来源。

## 新做帖与改帖

- “新做帖”在一个事务中创建帖子、V0 和首次排期。
- “编辑排期”只更正已有版本的资料、时间与状态，不增加版本号。
- “改帖”只能从原版本发起，自动生成下一版本号，必填改动类型、改动说明、修改目标、新文档和新应发时间。
- 改帖默认回到“待推广”。来源处于推广测试中时结案为“测试淘汰”，处于推广放量中时结案为“放量淘汰”，其他状态保持不变。
- 来源版本显示派生版本，新版本显示来源版本，支持在版本链之间识别关系。

## 后续规划（本阶段不实施）

- 日粒度全量表：按日期查看全量数据，也可按帖子查看连续每日数据；每日记录保存当日测试期/放量期快照。
- 阶段复盘：测试期、放量至今、周粒度（周六至周五）和自然月，全部从日粒度事实数据聚合。
- 数据填报：独立入口供负责人补录留资后的转化、成交或回款数据，具体字段和权限后续确认。
- 报表中心：周期结束自动生成周报/月报草稿，人工确认后冻结快照，再导出 PDF；推广帖使用每页 4 或 6 张卡片。
- 自动采集、定时任务、正式权限、PDF 和生产部署继续暂缓。

## 验证

- 数据迁移前后历史排期数量、ID、时间、状态和 `source_key` 不变。
- 新做帖只创建一个帖子、一个 V0 和一个排期；改帖依次创建 V1、V2。
- 编辑排期不增加版本；改帖保留来源版本并按规则结案。
- 并发创建相同下一版本时返回冲突，不产生重复版本。
- 验证桌面端、移动端、键盘操作、未保存提醒和减少动态效果模式。
- 执行 `pnpm db:check`、`pnpm check` 和 `pnpm build`；只在确认连接隔离开发库后执行迁移。
