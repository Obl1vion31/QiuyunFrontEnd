# Phase 06 Plan — 阶段复盘与会议中心

> 状态：06A 首轮实现完成，等待 development 真实口径验收；06A.1 控制台导航性能与 Sidebar 视觉优化已实施，等待真实网络连续切换验收。非推广阶段复盘与例会复盘已经拆分；正式数据自 2026 年 7 月开始，并按 T+7 → T+15 顺序补录。

## 一、目标与原则

Phase 06 将分散的内容执行、推广数据、Annual Plan 和会议结论组织成可追踪的阶段复盘。第一轮先解决“哪些内容尚未复盘、这次会议覆盖什么、结论如何留下来”，再逐步增加推广分析、周会生成和月度能力。

核心原则：

- **阶段由会议定义**：开始日、结束日可自由选择，允许 7 天、28 天或 36 天；默认截止会议前一天。
- **复盘节点只完成一次**：非推广帖允许在 T+7、T+15 各复盘一次；同一排期的同一节点被已完成复盘覆盖后，不再重复进入后续待办。推广阶段仍按不重叠 Stage 或日期片段覆盖。
- **未复盘自动结转**：跨周期或上次遗漏的内容自动进入下一次会议候选项。
- **自动数据、人工结论分离**：消耗、开口、留资、发布完成等从现有事实表汇总；判断、原因、策略和待办由人确认。
- **先确认再联动**：Annual Plan 和排期的写入必须预览并确认，不直接由报告自动改动事实表。
- **历史按当时事实解释**：帖子分类、推广身份或分类默认规则后来发生变化时，旧排期、旧 Campaign、旧指标和旧复盘继续使用当时快照，不以当前配置回算历史。

## 二、实施顺序

### 06A：非推广帖 7 / 15 天复盘

先建立最小闭环。只纳入 `2026-07-01` 起已实发的非推广排期，4—6 月不进入正式待办或 cohort。每条排期以 `actual_publish_at` 为起点生成 T+7、T+15，严格完成前一节点后才开放下一节点。非推广复盘独立于会议；例会只引用已完成结果。

数据源除 `operations_content_version`、`operations_content_schedule` 和 Annual Plan 外，还需要接入内容表现事实。第一轮至少支持：

- 点击率；
- 3 秒阅读率；
- 直接录入点击率、3 秒阅读率百分比和数据截止时间；cohort 使用同节点样本的百分比进行均值、最大值和最小值比较。
- T+7 读取发布后第 1—7 天累计事实，T+15 读取第 1—15 天；迟到数据或历史更正不得悄悄改变已完成复盘，需通过明确的“刷新快照”操作留下修订记录。

同类基准按“相同学科 + 相同帖子分类 + 相同复盘节点”建立 cohort。页面至少展示样本数、均值、最大值和最小值，并将当前帖子与 cohort 对照；建议同时预留中位数，避免极端值让均值失真。样本不足时只展示已有样本及明确提示，不给出好坏判断。默认只纳入同一指标口径、已到达该节点且数据完整的排期；是否限制近 90 / 180 天或同一自然年，实施前用真实数据分布确认。

页面能力：

1. 自动列出全部到期但尚未完成的 T+7 / T+15 节点，历史遗漏持续保留并标记逾期。
2. 同一帖子严格按 T+7、T+15 顺序开放；即使两个节点都已到期，也必须依次补录。
3. 每篇内容展示学科、分类、内容版本、应发/实发、当前复盘节点、指标数据截止时间、点击率、3 秒阅读率和同类基准。
4. 基准对照可展开查看样本范围、样本数、均值、最大值、最小值，以及当前值在范围内的位置；不同节点不可混算。
5. 每个节点只记录一项复盘结论；保存即完成该节点并开放已经到期的下一节点。
6. 排期 Inspector 展示 7 / 15 天复盘轨道，区分未到期、待复盘、已完成和已结转；已完成节点保持低强调，仍需处理的节点保持醒目。
7. 每个“排期 + 节点”全局唯一；历史通过明确的编辑入口修订。例会只引用结果，不拥有或覆盖原始复盘事实。

#### 分类、用途与推广身份变更

“推广讲义帖”未来可能改为“对外讲义”且默认不再推广，这类变化必须能在平台内完成，但不直接改写历史记录。

不建议只给分类字典增加一个覆盖全局的 `version`，因为分类名称、默认推广用途和某一条排期的实际推广事实是三个不同概念。建议拆为：

1. **稳定分类身份**：分类保留不变的 ID；改显示名称时创建新的分类规则版本，不修改旧快照中的名称。
2. **分类规则版本**：记录显示名称、适用学科、是否可选、默认是否推广、生效时间和变更说明。新建帖子读取当前生效规则；旧内容版本和旧排期继续引用创建时快照。
3. **排期实际身份**：每条排期仍独立保存“推广 / 非推广”，分类的默认值只帮助新建，不强制覆盖单条排期。
4. **用途变更事件**：已发布帖子从推广改为非推广时，在平台执行“变更后续用途”，填写生效时间和原因。系统先预览影响，再结束或保留已有 Campaign，写入用途历史；已有推广日度事实和推广复盘永久保留，生效后的复盘按非推广规则进入尚未到期的 7 / 15 天节点。
5. **禁止静默搬家**：历史推广数据不能因当前身份变为非推广而进入非推广 cohort；同理，过去的非推广数据不能因未来默认推广而被重算。cohort 使用指标发生时的身份与分类快照。

平台需要提供一个受控的“分类与默认规则”管理入口，以及单条排期 Inspector 中的“变更后续用途”动作。两者都展示变更预览与影响数量；分类规则只影响生效后的新建内容，批量迁移既有内容必须作为独立操作再次确认。

06A 不建设复杂绩效评分、AI 自动判断或直接智能排期。

### 06A.1：控制台导航性能与共享 Sidebar 视觉优化

当前业务页通过普通 `<a href>` 完整跳转。每次点击 Sidebar 都会销毁当前文档，等待目标 Astro 页面完成服务端数据库查询和 HTML 生成后再重建 Sidebar，因此数据库稍慢时会表现为整页长时间加载。推广日度复盘还依次查询 Campaign、Stage、Daily Metric 和待推广排期，等待时间会叠加。优化只调整共享壳层、导航行为和查询路径，不重做右侧业务页面。

#### 导航与服务端性能

1. 在业务控制台共享壳层引入 Astro 客户端路由能力，Sidebar 跨路由持久化，页面切换时只替换右侧 Workspace。
2. 点击导航后立即更新高亮，并在右侧顶部提供轻量加载进度；即使服务端仍在查询，Sidebar 不消失、不闪白、不位移。
3. Sidebar 链接按 hover、键盘 focus 和移动端 touch start 受控预取；不得在首屏一次性预取全部业务页并并发触发全部数据库查询。
4. 推广日度复盘的 Campaign、Stage、Daily Metric 和待推广排期改为并行查询；历史数据按当前筛选日期下推数据库，不读取全部历史后在页面内过滤。
5. “最新生命周期”只查询仍处于测试或放量中的 Campaign；已结束和已淘汰活动只进入历史视图。
6. 检查 Campaign 状态、Stage、`metric_date` 和常用范围筛选索引；稳定分类字典和低频设置数据只在证明有收益后增加短时服务端缓存。
7. 为业务页响应增加 `Server-Timing`，分别记录数据库查询和页面生成耗时，以真实数据决定后续优化，不用主观加载感替代测量。

性能验收目标：

- 点击后导航高亮在 50ms 内出现；
- Sidebar 在跨页过程中不销毁、不消失，布局位移为 0；
- 已预取页面目标 300ms 内出现右侧内容，未预取页面目标 800ms 内出现；
- 推广日度复盘数据库查询目标低于 300ms；若 development 数据库网络本身超过目标，必须通过 `Server-Timing` 明确区分网络与应用耗时。

#### Sidebar 视觉方向：Quiet Operations

Sidebar 从深色通用后台风格调整为与右侧工作区相连的浅色运营工作台。视觉重点是稳定、清晰和低干扰，不使用渐变或大面积阴影。

建议色板：

- Sidebar 背景 `#E7ECE8`；
- 页面纸张色 `#F7F8F5`；
- 主文字 `#17211C`；
- 次要文字 `#68736D`；
- 分割线 `#C9D1CC`；
- 当前模块蓝 `#315FD6`；
- 辅助墨绿 `#4E6B5B`。

结构与样式：

1. 保留 `232px` 桌面宽度，品牌区只保留“内容发布控制台”和一个小型 `OPERATIONS` 辅助标识。
2. 当前“总、排、日、非、会”汉字方块替换为项目内语义 SVG 线性图标，统一 `18px`，不再为图标单独增加方形底色。
3. 激活态使用完整的淡蓝灰圆角选择面、蓝色语义图标和加深文字，不叠加蓝色方块、状态线或外阴影；按压只提供轻微缩放和颜色反馈。
4. 桌面导航使用 `42px` 单行结构、`4px` 项目间隔、`10px` 左右内边距和 `10px` 图文间隔；移除逐项英文副标题，并按“计划与执行 / 复盘与沉淀”形成真实业务分组。
5. 删除无业务信息的 `INTERNAL ACCESS`；“报表中心”继续显示“计划中”，但与正式可点击导航保持清楚区别。
6. 系统设置和返回总枢纽固定在底部区；移动端继续使用统一底部导航，并保持当前页面、键盘焦点和减少动画偏好可识别。
7. Sidebar 的 DOM、样式、字体、盒模型和响应式规则只存在于共享组件；页面 Workspace 不得声明或覆盖 Sidebar 命名空间。

已完成共享业务壳层与持久化 Sidebar、延迟加载反馈、受控预取、日度与年度查询并行化、`Server-Timing` 和 Quiet Operations 视觉改造。下一步只需在真实 development 网络下完成六页连续切换与耗时验收；未经查询计划证明，不增加缓存或索引迁移。

### 06B：推广帖阶段复盘

明确“推广阶段复盘”的统计单元后，复用 06A 的会议、覆盖和结转机制。

建议统计单元：

```text
一条 Campaign 中一个已经结束的 Stage
或截至会议结束日被截取的开放 Stage 区间
```

这样测试期与放量期分别复盘，不把两个口径混成一条结论。数据从 Daily Metric 自动聚合：

- 总消耗、平台/实际开口、平台/实际留资；
- 实际开口成本、实际留资成本；
- 点击率：保留现有日度可空字段，阶段复盘确认统一口径后再启用汇总；
- 变现人数：阶段复盘新增人工确认值；
- 变现成本：`阶段总消耗 ÷ 变现人数`，分母为 0 时显示 `—`；
- 测试/放量日期、最终决定和 Campaign 生命周期。

复盘内容按“数据交叉关系”组织，而不是固定套用走势、结论、策略三段式。至少支持：消耗与真实开口、留资、变现之间的转化关系，同阶段不同帖子对比，以及测试到放量的变化。

### 06C：周例会与事项跟进

周例会是阶段复盘的主要组织入口，但周期仍可自定义。

会议页面建议分为：

1. **本阶段总览**：推广与非推广完成情况、关键数据、未复盘结转数。
2. **计划对齐**：从 Annual Plan 当月时间块与排期事实生成候选项，勾选已完成、延期和未完成。
3. **非推广复盘**：复用 06A 结果。
4. **推广复盘**：复用 06B 聚合与结论。
5. **待拍板事项**：需要负责人决定的问题。
6. **待验证 / 待解决事项**：负责人、目标日期、状态、进展记录，可跨会议持续跟进。
7. **会议结论与下阶段动作**：少量人工文字，其他内容从网页事实自动生成。

会议中心提供按时间倒序的历史列表和 Inspector，查看会议范围、参与复盘项、数据快照、结论及事项进度。已完成会议可生成适合打印的报告页面，并通过浏览器打印能力导出 PDF；第一轮不引入独立 PDF 服务。

### 06D：月例会与排期联动

在周度机制稳定后再建设：

- 上月与本月总消耗对比，由日度事实汇总，不重复录入；
- 私域新增人数按月人工填写；
- 本月主要动作、结论和下月整体策略；
- 按课程、帖子分类和整体三个层级汇总推广表现；
- 从 Annual Plan 拉取次月任务，确认执行数量与日期；
- 上月未完成项调整日期后形成排期变更预览；
- 用户确认后才写入真实排期。

“智能排期”必须先定义冲突规则、工作量边界、版本处理和撤销方式，06D 前不自动写入 Schedule。月度暂不重复建设周会的待验证/待解决事项，只展示跨月未完成项摘要。

## 三、候选数据模型

以下仅作为下一轮审视基础，实施前需再次确认字段与命名：

```text
stage_review_meeting
  会议身份、类型、开始日、结束日、会议时间、状态、总结快照

non_promotion_review
  排期、T+7 / T+15 节点、身份与指标快照、复盘结论和修改时间

content_performance_metric
  排期、统计截止日、点击率、3 秒阅读率和录入时间

stage_review_metric_snapshot
  会议完成时的当前指标、cohort 维度、样本数、均值、最大值、最小值和样本范围快照，避免历史指标或分类规则更正后悄悄改变旧会议报告

category_policy_version
  稳定分类 ID、显示名称、适用学科、是否可选、默认推广身份、生效时间和变更说明

schedule_usage_event
  排期用途从推广 / 非推广变更的生效时间、原因、操作者和变更前后快照

review_action_item
  待拍板、待验证、待解决事项，含负责人、目标日期、状态和来源会议

review_action_progress
  事项的跨会议进展记录

monthly_business_input
  私域新增等无法从当前系统自动取得的月度人工事实
```

非推广复盘以 `(schedule_id, checkpoint_type)` 建立唯一约束，确保三个节点各一条事实；会议通过范围或后续关联表读取完成结果，不改变复盘唯一性。推广覆盖继续按 Stage 或不重叠日期片段约束。

内容发布控制台建议逐步形成：

```text
推广日度复盘
非推广阶段复盘
例会复盘
├─ 周例会 / 自定义阶段
```

“C 推广 / GD 广”暂作为候选业务命名；在含义和使用人群确认前，页面优先使用“推广 / 非推广”，避免缩写造成理解门槛。

## 五、验收节点

### 06A 完成条件

- 自定义日期会议能正确识别到期的 T+7 / T+15 非推广节点和历史结转项；
- 同一排期能依次完成三个节点，同一节点不会重复进入下一次会议；
- 点击率与 3 秒阅读率按确认口径直接录入百分比，并保留数据截止时间；
- 相同学科、分类和节点的 cohort 能正确给出样本数、均值、最大值和最小值，且不混入不同口径或不同历史身份；
- 排期页面能辨识三个节点各自的未到期、待复盘、已完成和继续跟进状态；
- 在平台内修改分类默认规则或单条帖子的后续推广用途后，旧 Campaign、旧指标和旧复盘保持可查，未来待办按新身份生成；
- 会议结论、指标快照、分类规则版本、用途变更和覆盖关系均可追溯。

### 06A.1 完成条件

- Sidebar 跨页面切换持续存在，只替换右侧 Workspace，加载中有明确但克制的反馈；
- 受控预取不会在页面打开时并发请求所有业务页；
- 推广日度复盘的独立数据查询并行执行，历史范围筛选在数据库完成；
- `Server-Timing` 能区分数据库、页面生成和总响应耗时；
- 六个业务页面使用同一套 Quiet Operations Sidebar，跨页宽度、垂直位置、导航密度和激活态不跳动；
- Sidebar 共享组件继续隔离页面级盒模型、字体和行高，业务页面不存在独立侧栏结构或样式。

### 06B 完成条件

- 测试与放量阶段边界明确且不重复统计；
- 聚合值可从 Daily Metric 复算；
- 点击率、变现人数和变现成本口径经过确认；
- Campaign 生命周期与阶段结论能在 Inspector 中核对。

### 06C 完成条件

- 一次会议能组合计划对齐、推广/非推广复盘和事项跟进；
- 会议内容主要由系统事实生成，只需补充结论性文字；
- 历史会议可查看并能通过打印导出 PDF；
- 未完成事项能自动带入后续会议。

## 六、进入实施前需要确认

1. 点击率的原始分子 / 分母分别是什么，3 秒阅读率的分母使用曝光、打开还是其他平台口径；数据通过人工录入、文件导入还是现有来源取得。
2. cohort 默认时间窗使用近 90 天、近 180 天、同一自然年还是全部历史；低于多少个完整样本时只展示数据、不形成比较结论。
3. 已经开始推广的帖子切换为非推广时，开放 Campaign 是立即结束、指定日期结束，还是仅停止未来推广但保留开放状态；该选择会影响用途变更流程。
