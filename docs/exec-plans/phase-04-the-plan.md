# Phase 04 — THE PLAN：年度总周期规划

## 目标

总周期规划位于现有“帖子身份 → 内容版本 → 发布排期”的上游，用一个自然年度矩阵统一展示：

```text
年度总周期规划
├─ 总规划
├─ TMUA 细致规划
├─ STEP 细致规划
└─ 面试课细致规划
    └─ 有序规划行 → 一个或多个时间块
```

本阶段只建设独立的年度规划工作台，不自动生成帖子、内容版本或发布排期，也不改变现有三层内容模型。

## 已确认边界

- 默认页面同时展示总规划和所有学科细致规划；学科筛选只用于快速聚焦。
- 总规划由启用的细致规划自动计算，推广周期由规划行的独立汇总标记决定；总规划不提供普通规划行编辑器。
- 一条规划行属于一个年度和分区，拥有名称、顺序、可选学科/分类/课程名称、多个行级链接和多个时间块。
- 总规划行不强制关联学科、课程或帖子分类；详细规划行可以复用既有学科—分类关系。
- 课程名称只是规划行的可选补充信息，不建设课程树，也不作为默认页面层级。
- 时间块可以连续或不连续，但同一规划行内不能重叠；单月块的开始和结束月份相同。
- 时间块名称可以与一种可选数量规则同时保存。
- 矩阵颜色只表达科目，不使用深浅表达推广或数量规则。
- 弹性规划保存默认月频次，展示值按时间块长度计算，例如 3—7 月、每月 1 篇展示为 `1×5`。
- 硬性组合按正整数数组保存并保持顺序，例如 `3+3+4`。
- 主要文档链接属于规划行，一条规划行支持多个链接。
- 任何有效修改都会生成新版本；恢复历史必须生成新的当前版本，不能覆盖旧版本。
- 年度复制、自动生成排期、导入导出、正式权限、完整审计和报表能力暂缓。

## 数据方案

复用：

- `operations_subject`
- `operations_category`
- `operations_subject_category`

新增：

- `operations_annual_plan_year`：年度说明和更新时间。
- `operations_annual_plan`：规划行当前状态，保存年度、分区、名称、可选关联、顺序和当前版本号。
- `operations_annual_plan_block`：规划行的连续月份时间块及其可选数量规则。
- `operations_annual_plan_link`：规划行级 SOP 或帖集链接。
- `operations_annual_plan_version`：不可变 JSONB 快照、差异、修改说明、账号与时间。

主要约束：

- 规划行唯一键为 `year + section_key + row_name`，阻止同一分区内完全同名的重复行，但允许同一分类用于不同规划项目。
- 选择分类时必须同时选择学科，并通过复合外键保证分类属于该学科。
- 月份限制为 `1—12`，结束月份不得早于开始月份；同一行时间块重叠由服务端校验拒绝。
- 时间块限制弹性与硬性字段互斥。
- 版本号在单条规划行内唯一，更新接口使用预期版本号防止并发覆盖。

当前帖子、内容版本和排期表不增加规划外键。未来确需联动时再确认关系，不提前耦合。

## 面试课分类

- 将现有“出分喜报”显示名称改为“喜报”，保留内部 ID。
- 新增“面试课”和“面试信息”两个分类。
- 面试课启用：面试课、推广讲义帖、成功案例、喜报、面试信息、面试准备须知、创新帖。
- 现有面试课历史内容允许继续保持空分类，不猜测回填。
- 新建或编辑面试课内容时必须选择分类。

## 页面与交互

入口为 `/business/annual-plan`，名称为 `THE PLAN · 年度总周期规划`。

桌面端使用统一高密度矩阵：

```text
规划分区 | 沉淀模板 / 帖集 SOP | 规划项目 | 1月 | 2月 | ... | 12月
总规划   | ...
TMUA 细致规划
STEP 细致规划
面试课细致规划
```

- 左侧三列和月份表头在滚动时保持可读。
- 时间块跨越真实月份列，只展示一次名称和数量规则。
- 分区使用一致色系和文字标签，不只依靠颜色传递含义。
- 点击规划项目或时间块打开 Inspector；新建和编辑使用 Dialog。
- Inspector 展示关联、时间块、链接、当前版本、历史版本内容和恢复入口。
- 页面顶部展示年度说明和该年度最近更新时间。

移动端不压缩 12 个月，保留横向滚动，并让编辑器和 Inspector 使用窄屏可操作布局。

## 服务端操作

- 创建和编辑规划行及其时间块、链接。
- 编辑年度说明。
- 使用乐观并发读取版本列表和单个历史快照。
- 将历史快照恢复为新版本。

所有写入沿用现有同源检查、Zod 字段错误、Drizzle 事务和明确 HTTP 状态：

- `422`：字段、时间块或业务关系无效；
- `404`：记录不存在；
- `409`：重复规划行、并发冲突或历史引用失效；
- `503`：数据库不可用。

临时多账号 Basic Auth 的用户名作为基础修改标识写入规划版本；这不等同于正式审计系统。

## 实施与验收

- 仓库检查后确认目标开发库已经执行旧版 `0009`，但规划业务表为空；使用带空表断言的 `0010` 重建为新结构，避免静默丢失未来可能新增的数据。
- 一页可查看总规划和所有学科分区，并可按分区快速聚焦。
- 同一规划行可保存 3—7 月与 11—12 月两个不连续时间块。
- 弹性 `2×10` 与硬性 `3+3+4` 保存、展示和恢复后含义不变。
- 时间块名称与可选数量规则能够同时存在。
- 同一年度、同一分区和同名规划行不能重复；同一分类可用于多个不同名称的规划行。
- 所有实际修改产生版本；无变化保存不增加版本。
- 并发编辑返回冲突，不覆盖先保存的数据。
- 历史恢复产生新版本，不删除中间版本。
- 排期管理的新做帖、编辑、改帖和筛选能力保持不变。
- 执行 `pnpm test`、`pnpm db:check`、`pnpm check` 和 `pnpm build`。
- 只在确认连接隔离 Neon 开发分支后执行迁移。
