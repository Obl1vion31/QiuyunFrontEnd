# 已确认决定

本文件只记录已经确认、会影响后续工作的产品、结构和技术结论。

## 产品定位

- 当前产品暂称“前端团队管理系统”。
- 网站长期目标是承载前端业务工作、数据、规则、复盘和协作入口，不应停留在静态宣传页。
- 首页以部门工作流为主要叙事，呈现策划、内容、视觉、发布、用户触点和反馈回流如何组成完整流程；对外文案不强调个人或当前人员安排。
- 总枢纽首页是系统入口，不是整个系统，也不是实时业务驾驶舱。
- 前端负责从用户看见内容，到阅读、产生兴趣、形成咨询并完成有效交接的过程；最终销售成交仍属于销售侧边界。
- 原始业务数据不应主要存放在周报或月报中；报告是输出视图，不是事实来源。

## 当前页面边界

- 当前正式界面包含总枢纽首页、年度内容总周期规划和运营内容排期 MVP。
- 首页用于解释前端存在的意义、完整工作链路和后续系统入口。
- 首页首屏同时呈现工作台定位与前端使命：以 `FRONTEND CONTENT WORKSPACE` 说明平台属性，以 `WHY WE EXIST` 说明内容触达目标；不再设置独立的使命区块。
- 首页不展示实时数据、周报明细、月报明细、当前项目列表、完整业务排期或个人绩效薪资明细。
- 首页当前保留业务系统、组织与人员、绩效与报酬三个方向的入口概念。
- 业务系统入口连接 `/business/operations-schedule`；组织与人员、绩效与报酬继续保持占位或授权入口。
- 排期以“新做帖”和“改帖”区分内容生产动作：新做帖建立 V0，改帖从原版本派生 V1/V2 并保留版本链；“编辑排期”只更正资料、时间与状态，不代替改帖。
- 创建改帖只填写一项“具体改动说明”，说明具体改动部分、改动原因与希望达到的效果；不再单独记录改动类型和修改目标。
- 帖子身份、内容版本和发布排期分别保存；历史排期不猜测关联，每条作为独立 V0。
- 学科与帖子分类是两个独立的固定字典，通过映射决定学科可用分类。面试课启用面试课、推广讲义帖、成功案例、喜报、面试信息、面试准备须知和创新帖七类；旧面试课内容允许保留空分类，新建或编辑时必须选择有效分类。
- 年度细致规划行优先使用“学科 + 帖子分类”作为显示名称；帖集使用统一的 ` [帖集]` 后缀。机器关联始终以 `subject_id + category_id` 为准，不根据中文名称反查。
- 总周期规划位于具体内容排期上游，默认以一个自然年度页面同时展示总规划和各学科细致规划，不在当前阶段自动生成帖子、内容版本或排期。
- 年度规划以“分区 → 有序规划行 → 一个或多个时间块”组织。总规划行不强制关联学科、课程或帖子分类；细致规划行可以复用现有学科与分类关系，课程名称仅作为可选信息。
- 总规划不再由用户填写，而是从启用的细致规划自动汇总：全部启用行形成发帖周期，标记为“计入推广周期”的启用行形成推广周期。旧总规划记录只保留历史，不进入页面和计算。
- 时间块保存开始与结束月份、名称和可选的一种数量规则。同一行可以有多个不连续时间块但不能重叠；弹性频次按月频次和块长度表达，硬性组合保持正整数顺序。
- 年度规划的主要 HTTP/HTTPS 链接属于规划行，一行可以保存多个。所有有效修改生成包含规划行、时间块和链接的不可变版本快照，恢复历史时创建新版本，不覆盖旧历史。
- 年度规划在正式运营修改开始前统一视为初始化 V0：新建规划行为 V0，首次实际修改后进入 V1。2026 年 7 月 28 日以前为搭建和录入产生的中间版本历史不作为业务变更历史保留，只保留每条规划的当前内容并归档为 V0；该规则不改变内容发布排期自身的新做帖 V0 / 改帖 V1+ 版本链。
- 细致规划的显示顺序跟随帖子分类字典；停用行默认隐藏且不参与汇总。SOP 在矩阵中只显示链接箭头，链接名称不作为主要业务信息。
- 规划行唯一约束为同一年、同一分区、同名规划项目唯一；同一分类可以服务多个不同用途的规划行。
- 排期支持新做帖、完整编辑和从原版本发起改帖，不支持删除、通用上传导入或导出。
- 内容发布控制台包含总周期规划和排期管理两个已实现入口；日粒度全量复盘、阶段复盘和报表中心仍只显示规划状态。
- 排期管理使用统一的按日期分组时间轴台账承载大数据量，并保留月历切换；推广中不再作为独立看板，而是同一数据集的筛选视角，并拆分显示测试中与放量中数量。
- 桌面端使用 `Sidebar + Toolbar + Inspector + Sheet` 结构：Inspector 查看当前帖子详情和版本链，Sheet 承载新做帖、编辑排期和创建改帖；移动端导航转为底部 Bar。
- “推广”只指花钱测试或放量的内容；非推广帖无论来源阶段如何描述都保存为非推广，不进入推广看板。推广阶段独立保存为非推广、待推广、推广测试中、推广放量中、推广周期已结束、测试淘汰和放量淘汰；推广周期已结束表示内容未被淘汰而自然结束一轮推广，测试淘汰表示测试后停止投入，放量淘汰表示进入放量后停止投入，“推广中”只统计推广测试中和推广放量中。
- 应发与实发精确到分钟并按 `Asia/Shanghai` 解释；完成情况不由用户选择，而是自动归一化为待发布、按时发布或延期发布。实发严格超过应发 12 小时时必须填写延期原因，尚未实发但已超过阈值时显示“逾期未发”。
- 新排期的项目文档名称与 HTTP/HTTPS 链接必填；历史 Excel 数据允许保留缺失链接，但编辑时必须补齐。
- 一次性历史数据导入必须使用默认只读预检、显式写入、事务保护和幂等键；完成后移除批次脚本，不在核心文档保留具体文件名、月份、条数或清理结果。当前不建设通用上传或自动同步。
- 内容发布控制台后续方向包括日粒度全量表、阶段复盘、独立数据填报和报表中心；当前仅预留日粒度全量复盘、阶段复盘和报表中心入口，具体数据字段与页面能力进入对应阶段时再确认。

## 技术基线

- 技术栈采用 Astro 4 + React 18 + TypeScript，以兼容本地 Node `18.19.1`。
- 包管理器采用 `pnpm`。
- 样式以 Astro scoped CSS 为主，复杂交互组件可以使用 React 和 CSS Modules。
- 首页内容集中维护在 TypeScript 配置中，避免正文散落在组件里。
- 当前只做本地验收，不配置生产部署。
- 排期 MVP 使用 Neon 托管 PostgreSQL、Drizzle ORM、标准 `postgres` 驱动和 Astro hybrid 输出；首页继续静态生成。
- 业务页面和写入接口使用临时多账号 HTTP Basic Auth，各账号权限相同；新配置缺失时兼容旧单账号变量，所有有效凭据缺失或多账号 JSON 无效时拒绝访问。总周期规划版本记录凭据用户名作为基础修改标识，但这不是正式权限或完整审计系统。
- 当前不建设独立后台、正式登录权限、自动采集或报告生成。

## 文档基线

- 仓库主要内容目录维护各自的 `README.md`，用于说明目录用途、文件职责和安全边界；`src/pages/` 除外，避免 Astro 把说明文档生成为新路由。
- `docs/` 使用 `README.md` 导航，长期结论仍只进入 `DECISIONS.md`、`DESIGN.md` 和 `ROADMAP.md`。
- 产品、结构和技术的已确认结论统一进入本文件。
- 视觉与交互规则只在方向获得确认后进入 `DESIGN.md`。
- 当前工作、下一步与暂缓事项进入 `ROADMAP.md`。
- 不再常规维护独立的产品定义、结构说明、执行计划、执行结果和 Reference 生命周期文档，也不为停用类型保留空目录；历史由 Git 保存。
- phase 02、phase 03 和 phase 04 的执行计划或结果文档，是用户明确要求长期保存的例外。

## 当前视觉状态

- 原首页视觉和布局已被“内容穿越总控台”方向替代。
- 首页是全站唯一允许大胆视觉表达的页面；后续页面和首页后半段保持简洁、清晰和低动效。
- 首页 Hero 使用大量 3:4 帖子封面建立内容纵深，滚动时封面从远处向前穿过工作台。
- 初始构图以两层顺时针顺序和轻微渐进尺寸形成静态螺旋感；螺旋只属于初始大小关系，不改变滚动轨迹。
- 六条轨道表达策划、内容、视觉、发布、用户触点和复盘依次衔接并持续回流的部门工作流。
- 必须保留前端宗旨：让用户愿意点击、愿意读且读完，并愿意进一步了解或咨询。
- 首页已接入八张用户提供的 3:4 内容封面，每张素材在循环内容流中只保留一个实例，避免同屏出现重复封面；代码封面板继续作为未配置图片时的备用显示。
