# 减少动态页面与提醒的无效读取

状态：已自检，待发布。基线`261b269`，分支`codex/network-transfer`；保留原工作区修改。全部业务样本来自独立PostgreSQL／PGlite，不写共享Neon。

## 改动与结果

| 同一套隔离样本 | 原版 | 候选 |
| --- | ---: | ---: |
| 单次提醒HTTP请求的数据库返回字节 | 317998 B | 4714 B |
| 进入排期页后的额外提醒API | 1次 | 0次 |
| 依次悬停三个未访问模块 | 3次动态页读取 | 0次 |
| 实际点击进入非推广页 | 正常 | 1次读取，正常 |

样本包含36条排期及较长的历史文本；提醒读取实传字节减少98.5%，全部计数及对应ID一致。此为本机数据库协议字节，含该请求的数据库会话读取，不代表整站或Neon正式月流量比例。[原版](validation/before.json) · [候选](validation/after.json) · [对比数据](validation/comparison.json)。

- 动态业务HTML仅在实际导航读取；悬停、焦点与触摸按下不预先触发数据库查询，保留ClientRouter和原加载反馈。
- 排期页复用本次已计算的SSR提醒，侧栏跨页接收新结果；其他页面继续走原提醒API。没有跨请求业务缓存。
- 提醒只读取所需排期字段、当前修订理由日期键和待审目标，不取回改期历史、理由正文及更正历史；具体内容仍通过原详情查看。
- 每分钟、返回与保存后更新保留。读取期间发生保存会随后再读；旧响应不能覆盖新页SSR数字，失败保留计数并提示。登录、账号停用、权限和旧版本保存保护保持。

## 实际验收

261项规则、schema检查、类型检查（0错误／0警告，26项既有提示）、Node／Vercel构建、公共UI、排期审批／延期／节点恢复、12组真实PG并发保存及17个首屏场景通过。新专项核对两小时边界、旧修订排除、管理员／员工计数、实际导航、一分钟计时器、慢读取中的保存刷新、503恢复及迟到响应隔离。

原生Chrome前台／同窗口后台／另一角色实际观察66519ms，协作请求均为0，后台提醒为0，前台提醒继续更新；此批为一分钟观察，不冒充五分钟。[后台记录](validation/native-background.json)。午夜／T+1业务刷新、月度返回刷新与例会本地时钟保持。
