# 推广复盘：前后安排重叠时的保存检查

状态：已发布、已自检，待用户反馈。应用 `0e8951b`，基于正式源码 `6953857`；本批使用实际 Vercel 运行包、隔离 PostgreSQL、固定上海时钟和独立测试账号。部署 `dpl_6TkXkN4vJDAdSavNgHU47ygciBCF` 已归档、READY 并指向正式域名。

## 查明的问题

11 日淘汰、10 日最后投放，日期本来就没有矛盾。上一批已修正程序将这类正常记录拒绝保存的问题；本批扩大检查，又复现了另一类误拦：当天已淘汰或结束，后一天旧例会重复相同状态，程序把正常保存当成了修改例会，要求填写理由。

旧实际包的 64 组检查中有 6 组因此失败，分别是测试淘汰、放量淘汰和推广结束的双角色组合。修复只兼容已经存在的相同状态安排；创建、修改例会决定仍按现行规则执行。页面相应显示“无需后续动作”，移除无效的空修改入口。

| 检查的情况 | 结果 |
| --- | --- |
| 测试中、测试暂停、测试结束待定、放量中、放量暂停，与当天或后一天安排重复 | 正常保存 |
| 原计划暂停／待定、当天实际测试；原计划放量暂停、当天实际放量 | 合法当日更正后正常保存 |
| 原计划测试／放量、当天更正为暂停／待定；暂停与待定更正 | 正常保存 |
| 测试淘汰、放量淘汰、推广结束，后一天旧例会重复相同状态 | 已修复误拦，正常保存 |
| 已淘汰或结束，后一天却安排继续原测试 | 继续拒绝；提示两天日期和状态，保留输入 |
