## 样例与结果

| 项目 | 测试结果 |
| --- | --- |
| 原始月排期V0落在本周 | 5篇 |
| B从本周移至下周 | 原11月3日，调整为11月10日，原因可展开 |
| 本周新增F、G | 2篇 |

月排期定稿、员工改期／新增／发布，以及周会会前与会后定稿均经过真实业务接口。历史样例使用固定业务时钟，并将两条新建测试记录的数据库创建时间对齐到11月3日；没有改动业务算法、接口响应或截图DOM。

管理员test_admin、员工test_employee分别在1920／1440／1024×1000打开同一份会后定稿，键盘展开明细，查看8条排期及调整原因；24张截图已查看。1024表格在本容器横向滚动，分别留有左侧记录与右侧原因画面。

另实测：

- 后补G的11月7日实发，重新读取材料变为实发6、未登记1。
- 已有周会定稿快照仍保持实发5、未登记2，未被新数据覆盖。
