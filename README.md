# 前端团队管理系统

面向内容运营的团队工作台：年度总周期规划、帖子版本与排期、推广每日／历史复盘、非推广首轮／二轮复盘与周／月例会阶段复盘。

- [公网工作台](https://qiuyun-frontend.vercel.app/business/operations-schedule)
- [最新交接](handoff.md)：最近交付、验证范围和接手顺序。
- [文档导航](docs/README.md)：业务规则、代码、数据库和发布说明。
- [视觉验收图库](verified/README.md)：按时间保存的最终界面截图，可直接查看并反馈。

## 本地启动

使用 `.nvmrc` 指定的 Node 22 和 pnpm 9.15.9：

```bash
pnpm install
pnpm dev
```

按 `.env.example` 配置数据库、独立认证密钥和本机认证 URL；配置值不提交。需要接入现有库或创建账号时，先读[数据库指南](docs/database-guide.md)。

**本地和公网共用已选定的 Neon 分支，网页写入会同时影响两端。** 测试使用隔离数据库。历史迁移包含特定导入校验，不能在空库中直接重放为初始化。

## 技术与命令

Astro 5、React 18、TypeScript、Neon PostgreSQL、Drizzle ORM、Better Auth。首页静态生成，业务页面和 API 动态运行；本机采用 Node adapter，公网采用 Vercel adapter。

```bash
pnpm check
pnpm test
pnpm db:check
pnpm build
```

浏览器验收及本机工具配置见[测试说明](tests/README.md)。数据库结构通过追加迁移更新；网页业务数据保存后立即生效，不需要重新构建或迁移。

## 前端开发与验收

每次页面改动先读 [AGENTS](AGENTS.md)、[设计规范](docs/DESIGN.md) 和[共享界面接入实例](docs/code-study.md#共享界面接入)，主动使用现有 `frontend-design` Skill 的审查方法，检查组件及控制器后再修改。完成前实际运行页面、查看浏览器渲染并自主修正视觉问题，不能以构建或断言通过代替验收；受限部分须明确说明。跨页容器、相邻视图的公共节点和 Inspector 都按[浏览器验收标准](tests/README.md#界面一致性验收)核对；`pnpm test:ui` 提供可重复的隔离验证。

工作台自托管 MiSans 5.0.0，公共读取超过 500ms 显示目标区域单处反馈，所有站内导航共用 120ms 顶部进度。整个工作台使用同一套视觉和交互基准；局部操作只改变必要内容，空态、历史版本和异步内容同样遵守字体与组件规范。每次交付检查布局稳定、同类反馈、文案必要性和任务范围，突破既有基准须先说明并取得确认。

公共模式优化默认检查并同步全部适用页面，用户指定局部时遵从其范围；先判断信息与操作语义，再组织视觉，不强制所有业务页面采用相同结构。

完整日期时间统一复用 `BusinessDateTimeFields` 的日期／时间拆分选择；原字段、时间含义与必填规则保留，仅日期不增加时间。控件一致性同时验收实际操作模式与计算字体，公共规范变更同步适用位置。

展示方式复用 `BusinessViewSwitch`，编辑表单抽屉复用 `BusinessFormSheet`，居中任务使用 `BusinessFormDialog`，常规表单与筛选显式接入共享样式；筛选、表单和操作区按功能分组并使用共享控件规格，接入入口见上述实例。

## 日常使用与发布

- 年度规划：`/business/annual-plan`，总规划由学科细致规划自动汇总。
- 帖子排期：`/business/operations-schedule`，新做帖建立 V0，修改内容建立 V1+，默认按月历查看，“排期待审”沿用台账并在详情处理申请差异；满应发 2 小时未登记提醒“尚未登记”，按真实发布时间判延期；发布统一登记时间与帖子链接，支持完整分享文案和未来时间。
- 推广日度：`/business/daily-promotion-review`，上方生命周期节点与累计效果、下方按活动日期直接单行填写；T+1 开放，状态气泡可再次更正当日、恢复误选前状态，次日安排独立。暂停／待定每天仍需复盘，新草稿默认零且允许真实跑量；淘汰后可按笔记 ID 补录残留。版本旁提示查看笔记 ID，首次 ID 用小气泡补齐并随复盘保存；待定默认继续待定，支持当前可填队列一键原子保存。名称仍可打开资料 Inspector。
- 推广历史：`/business/daily-promotion-review?view=history`；新增阶段复盘在周例会完成，旧阶段快照链接继续只读。
- 非推广复盘：`/business/non-promotion-review`，首轮／二轮指标、学科分类筛选、同学科同帖子类型的六列分类均值（两轮上下排列）、分类下方展开明细／历史数据总览，以及单轮／整篇不复盘与恢复；实验日期原列显示发布日期至该轮应复盘日。行、标题与“点击录入／查看详情”统一进入资料与录入 Inspector，文档、小红书和完整排期可另页查看。
- 例会：`/business/meeting-review`，周／月例会表格总览，进入会议后独立显示，推广候选自选并提前提示非推广全量处理，确认后三列同行等高卡片内联填写，非推广按实发日默认7／15天截止并提供标题旁资料气泡，推广与非推广统一；本帖历史优先、历史同类辅助。定稿以本期结果、核心结论与下一步为先，草稿保留填写顺序。会前冻结材料后可在展示页直接讨论文字和安排，保存讨论稿不生效；会后定稿执行次日安排与事项流转并自动归档版本PDF，历史默认折叠，版本追加且保留来源；账号权限：`/business/settings`。

账号分为管理员和员工；两种角色均可处理日常复盘和单帖暂停。规划行内可由管理员追加全站学科及分类；推广待定下一步可重新测试，按轮独立统计。管理员可在系统设置中按员工账号配置年度规划、排期各操作的关闭／直接生效／审核后生效。默认员工年度只读，超时未登记改期需审核，已有实发时间更正等敏感操作关闭；延期仅按最新排期满 2 小时判定，改期生效后清除旧延期原因。完整权限及业务口径见[已确认决定](docs/DECISIONS.md)。

开发与修正在工作分支完成必要测试与视觉自检后，默认直接通过既有 Vercel CLI 流程发布公网并核对结果，无需逐轮确认；用户通知变更前持续有效。合入 `main` 仍需独立确认，Git 推送不自动部署。发布、临时隧道和回滚入口见[部署指南](docs/deployment.md)。
