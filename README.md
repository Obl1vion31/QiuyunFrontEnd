# 前端团队管理系统

正式发布先保存本机运行包，再切换版本并清理旧部署；日常入口见[发布归档与保留规则](docs/deployment.md#正式运行包归档与旧部署清理)。

面向内容运营的团队工作台：年度规划、帖子版本与排期、推广与非推广复盘、月度运营及周／月例会。月会先确认预排期，员工在原月历落实首轮安排，整月提交管理员核对；核对通过后整场月会与计划永久封存。后续排期调整填写原因并留档，不改月会基准。

首页“组织与人员”进入 `/organization`，以“岗位与协作／人员任职”查看职责、交付、资料和兼任关系。管理员维护职责与任职，员工只读；人员复用现有账号，岗位与系统权限分开。

排期详情、编辑、发布登记与创建改帖在同一个右侧浮层内切换，月历不挤压；保存局部更新后返回详情，整月说明草稿保留。最新有效版本登记实发后才能创建改帖；取消新版排期后，原已发有效版本恢复资格，新编号仍按全部历史递增，取消记录保留。排期表保持当前任务视图；预排期及Week执行、具体改期、内容与设置在详情与查帖中分组追溯。

首轮排期从计划带入分类默认，人工改选保留；双方保存说明草稿，管理员最终定稿前员工可继续增改，同原Week微调免理由、跨原Week需理由。管理员一次定稿为月排期V0；后续带理由直接调整，取消仅管理员。周会、月会和月度运营共用V0执行对照，净构成与原始变更均可追溯；不增加在线编辑锁或协作轮询。

预排期从2026-11开始采用，2026-10及以前默认按历史月排期V0维护，后续调整填写原因；历史已发帖可按原有版本链创建改帖，再校验目标月份。兼容读取不补造确认记录或历史基准，也不重编号帖子版本。

未发布排期可拖到空日期保留时刻，目标日已有内容时选择加入或与某篇对换；详情内的“移动／对换”提供相同的键盘操作。对换事务内同时保存双方时间及历史，版本变化时重新核对。编辑按实际字段判断未保存，异步回填与改回原值不误报。系统设置的使用说明按常用操作、业务条件与高影响操作编排全站主要按钮和权限，保留月会与排期操作图；8号新建周会默认复盘至7号，当天调整8号以后的执行安排不改写截止对照。

周例会按实际内容变化建立修订。月会封存前展示最新月度材料及完整预排期，管理员核对通过时才切换为最终实际月计划；历史版本及 PDF 保留原快照；最终封存后仅核心结论、下一步行动可直接保存文字修订并追加V号；原统计、计划与事项冻结，旧版本和PDF保留。

推广每日复盘只保留昨日数据日的已保存行和原控件，显示“已保存／继续编辑”，锁定字段共用灰色禁用外观，点击继续编辑后才可更正该日状态及次日安排，刷新保留；更早日期即使今天补录或修改也只进入历史，权限及T+1口径保持。

管理员可从系统设置的“接入管理”维护聚光报表只读授权、查看账户及检查离线报表连接，页面列出接口、字段和当前用途。推广复盘继续沿现有人工录入，不自动覆盖事实。

## 本地启动

使用 `.nvmrc` 指定的 Node 22 和 pnpm 9.15.9：

```bash
pnpm install
pnpm dev
```

本机开发使用上海服务器的独立 `qiuyun_dev`，通过仅监听本机的 SSH 通道连接；`pnpm dev` 会先检查目标及通道，再启动网站。正式网站继续使用 Vercel 中的 Neon 配置，两边数据不自动同步。

开发账号、维护账号及登录密钥保存在 Git 公共目录下被忽略的 `.tools/private/`；根目录与开发工作树的 `.env` 只提供开发应用账号。测试账号与样例位于开发库，样例排期月份为 `2026-10`，当前月份继续遵守正常月会门禁。配置、初始化和故障处理见[数据库指南](docs/database-guide.md)。历史迁移包含特定业务批次校验，不能直接在空库重放。

## 技术与命令

Astro 5、React 18、TypeScript、Neon PostgreSQL、Drizzle ORM、Better Auth。首页静态生成，业务页面和 API 动态运行；本机采用 Node adapter，公网采用 Vercel adapter。

| 命令 | 使用时机 |
| --- | --- |
| `pnpm check` | 需要单独类型检查、且本轮不构建时 |
| `pnpm build` | 需要运行产物或发布应用时，已包含类型检查 |
| `pnpm test` | 需要完整业务规则回归时；局部改动优先选相关用例 |
| `pnpm db:check` | schema或迁移变化时 |

命令按[本轮检查选择](tests/README.md#本轮如何选择检查)使用，不作为每次串行清单；同一输入的类型检查、构建及已覆盖测试不重复执行。仅未被应用读取的文档／规范修改，检查差异与链接后同步main即可，不构建或部署网站。PDF仅在实际影响打印链路、依赖或打包时验证，细则见[部署指南](docs/deployment.md)。数据库结构通过追加迁移更新；网页业务数据保存后立即生效，不需要重新构建或迁移。

动态业务页只在实际导航时读取；排期侧栏复用本页已有的提醒结果，提醒查询只取计数所需字段。前台每分钟、返回页面及保存后的提醒更新保持，身份和权限检查继续逐次执行。

例会决定、历史比较、月度事项和帖子关联查询由数据库先返回所需字段；推广日度及周会材料在本次请求内复用上下文。指定例会版本的完整材料、历史与打印继续保留。

私域按推广学科／用途与非推广自定义来源分开维护，推广成本按有效明细人次汇总；仅排期且人数全空的用途不进入统计，真实零记录保留。月度与当前月会按桌面每行三项展示六项结果，总消耗及五项单位成本在右侧显示最多六个月的走势，仅用真实有数据的首尾范围；有效月份均标点，历史空心、最后有效月实心，点击只展示月份与数值、不放大位移；无可比数据时提示“暂无对比数据”，不默认展示月份。来源直接在结果表下面展开，默认折叠。历史抽屉仅保留所选月六项结果及必要人数，完整资料从“查看该月明细”进入。旧口径只读保留，旧封存材料不实时补算；验收与发布见视觉验收图库。

## 前端开发与验收

页面改动先读[AGENTS](AGENTS.md)、[设计规范](docs/DESIGN.md)及相关[共享界面接入实例](docs/code-study.md#共享界面接入)，按实际任务使用Impeccable等可用设计Skill，检查组件及控制器后修改。完成前实际运行受影响页面、查看渲染并修正视觉问题，不能以构建或断言代替验收。普通局部改动检查常用桌面及关键状态；布局／断点、权限或首屏链路变化时才增加对应视口、角色或慢请求矩阵。共享几何与Inspector变化可选`pnpm test:ui`，其他专项按[测试标准](tests/README.md#本轮如何选择检查)选择，受限部分明确说明。

工作台自托管 MiSans 5.0.0，公共读取超过 500ms 显示目标区域单处反馈；真正切页采用 A 方案：保留当前页，等待超过120ms显示顶部蓝色流动细线，超过1200ms补充短提示，就绪后原位柔和交接；快速就绪省略等待动效。整个工作台使用同一套视觉和交互基准；局部操作只改变必要内容，空态、历史版本和异步内容同样遵守字体与组件规范。每次交付检查布局稳定、同类反馈、文案必要性和任务范围，突破既有基准须先说明并取得确认。

工作台各模块的页面外层共用工作区全宽与正文边距，根容器不另设限宽或重复留白；表单和阅读内容在内部按用途控制宽度。跨页验证比较正文与实际一级面板的左右边界。

已认可的透光磨砂材质与语义化微交互覆盖全部模块，排期同样接入；主要容器承载光影，数据与操作保持清晰稳定，规则见设计规范。

公共模式优化默认检查并同步全部适用页面，用户指定局部时遵从其范围；先判断信息与操作语义，再组织视觉，不强制所有业务页面采用相同结构。

完整日期时间统一复用 `BusinessDateTimeFields` 的日期／时间拆分选择；原字段、时间含义与必填规则保留，仅日期不增加时间。控件一致性同时验收实际操作模式与计算字体，公共规范变更同步适用位置。

展示方式复用 `BusinessViewSwitch`，编辑表单抽屉复用 `BusinessFormSheet`，居中任务使用 `BusinessFormDialog`，常规表单与筛选显式接入共享样式；筛选、表单和操作区按功能分组并使用共享控件规格，接入入口见上述实例。

## 日常使用与发布

小红书聚光接入先完成应用创建及管理员授权；正式回调地址为 `/api/integrations/xiaohongshu/callback`，当前仅申请 `report_service` 报表读取权限。服务端凭据配置、授权入口和安全边界见 [接入说明](src/integrations/README.md)。现有业务复盘仍按原入口保存。

周／月例会新生成PDF统一使用A4竖版，保留完整数据、中文文字与版本页码；已有同一冻结内容的横版归档继续复用。浏览器直接打印会展开冻结依据，结束后恢复原折叠与滚动。

- 年度规划：`/business/annual-plan`，总规划由学科细致规划自动汇总。
- 帖子排期：`/business/operations-schedule`，新做帖建立 V0，修改内容建立 V1+，默认按月历查看，“排期待审”沿用台账并在详情处理申请差异；满应发 2 小时未登记提醒“尚未登记”，按真实发布时间判延期；发布统一登记时间与帖子链接，支持完整分享文案和未来时间；要求同步朋友圈的首次登记须确认朋友圈及对应需求均已发送。
- 推广日度：`/business/daily-promotion-review`，上方生命周期节点与累计效果、下方按活动日期直接单行填写，未开始／首次待定同表显示禁用指标，状态下设置安排，待定截止可空；T+1 开放，状态气泡可再次更正当日、恢复误选前状态，次日安排独立。暂停／待定每天仍需复盘，新草稿默认零且允许真实跑量；淘汰后可按笔记 ID 补录残留。版本旁资料气泡查看项目文档、帖子链接和笔记 ID，首次 ID 用小气泡补齐并随复盘保存；待定默认继续待定，支持当前可填队列一键原子保存。资料在原行就近查看。
- 推广历史：`/business/daily-promotion-review?view=history`；新增阶段复盘在周例会完成，旧阶段快照链接继续只读。
- 非推广复盘：`/business/non-promotion-review`，新做帖选择纯推广／推广后持续复盘／非推广常规／非推广即时，原帖共用7／15天及自定义累计节点，待复盘只展示任务信息并在原Inspector完整录入；曝光量／阅读量计算点击率、手填3秒阅读率，学科分类筛选、按常规／即时／持续组织结果，同学科同帖子类型的七列分类均值含阅读量及独立有效样本（两轮上下排列）、比率细轨与持续节点真实日期趋势、分类下方展开明细／历史数据总览，以及单轮／整篇不复盘与恢复；实验日期原列显示发布日期至该轮应复盘日。行、标题与“点击录入／查看详情”统一进入资料与录入 Inspector，文档、小红书和完整排期可另页查看。
- 月度运营：`/business/monthly-operations`，员工与管理员共用自然月看板，按最新排期核对发布、延期及改期去向；延期率可选全部／运营原因，共用已登记发布分母，分布区分运营、非运营与未归因。按实际消耗日查看推广投入、分类成本与已确认测试空跑，数字可追溯具体版本／轮次。手机从账号菜单进入。
- 例会：`/business/meeting-review`，周／月例会紧凑列表总览，进入会议后独立显示，周会准备区确认候选及完整性，缺项跳转原入口补齐后进入逐帖比较卡；月会先看完整经营结果，不逐帖复盘；非推广只读引用，原入口按实发日加7／15天、前后各1天且不晚于昨天填写，保留标题旁资料气泡；推广本帖历史优先、历史同类辅助，率使用pp差值与单处样本量。周会会后定稿对员工和管理员开放；月会首次确认预排期与最终封存仅管理员。定稿以本期结果、核心结论与下一步为先，草稿保留填写顺序。最新有效版本可切换只读／编辑，保存自动追加版本，生效日前可确认回溯；会后定稿执行次日安排与事项流转并自动归档版本PDF，历史默认折叠，版本追加且保留来源；账号管理与操作授权：`/business/settings`。

账号分为管理员和员工；两种角色均可处理日常复盘和单帖暂停。帖子类型、默认运营类型与推广用途由管理员在系统设置按学科独立维护；推广待定下一步可重新测试，按轮独立统计。测试暂停可恢复原轮或重新测试新轮，结束待定只能重新测试新轮；生命周期历史只修改当天安排，前后衔接合法并确认三天上下文后保存；不能衔接会明确指出日期，不自动删除或同步后续。年度规划与日常业务填写、更正和修订全员同权，保留实际修改人；管理员只为特殊排期操作配置授权，预排期确认和最终封存保留管理员限制。普通排期增改直接生效，已有实发时间更正等敏感操作沿用现行授权；延期仅按最新排期满 2 小时判定，改期生效后清除旧延期原因。完整权限及业务口径见[已确认决定](docs/DECISIONS.md)。

管理员和员工均可进入系统设置。员工默认阅读[使用说明](https://qiuyun-frontend.vercel.app/business/settings?view=guide)，五个公共章节可见（含推广历史更正）；维护入口和账号／授权管理仅管理员可见，管理接口保持原权限。

开发与修正在工作分支完成必要测试与视觉自检后，默认直接通过既有 Vercel CLI 流程发布公网并核对结果，无需逐轮确认；用户通知变更前持续有效。用户于2026-10-31进一步授权，通过上述验证后可直接同步并推送 `main`；推送前核对远端，Git 推送不自动部署。发布、临时隧道和回滚入口见[部署指南](docs/deployment.md)。

实时编辑共享已停用，不显示占用或阻止他人编辑。普通内容、说明和指标按最后一次成功保存生效并保留历史；历史影响更正及管理员封存核对实际预览版本。业务失败在原位置说明原因、保留输入，不强制整页刷新。登录、权限、审批及排期业务提醒继续保留。

登录支持账号或完整用户名。管理员在系统设置新增员工／管理员、修改账号及用户名，统一防重；修改保持原用户身份及历史，已有角色保持。账号约束迁移先冲突预检及备份，不自动重命名人员。

推广后持续复盘在建帖时填写最终复盘日期；本版推广正常结束次日起，每满7天设置一个截止节点，最终日期不足7天也收尾，截止次日录入。
