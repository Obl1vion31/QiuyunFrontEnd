# `drizzle/` 数据库迁移

本目录保存由 `pnpm db:generate` 生成或为受控数据迁移编写、经 `pnpm db:check` 检查的 SQL 迁移。迁移应与 `src/db/schema.ts` 同步提交，但不得写入连接串、密码或真实业务数据。

`0005_content_versions.sql` 将原排期中的内容资料迁移到帖子与版本表，每条历史排期建立独立 V0，并保留排期 ID、状态、时间和导入标识。执行前必须确认 `.env` 指向隔离的 Neon 开发分支。

`0006_split_discarded_promotion_statuses.sql` 将旧通用淘汰状态迁移为测试淘汰，并按固定 Excel 来源行把非讲义帖的“推广已下架”从推广周期已结束纠正为测试淘汰。

`0007_two_level_post_categories.sql` 建立学科与帖子分类字典，按固定来源行完整回填 53 条历史内容，并把改帖记录收敛为单一“具体改动说明”。迁移内置数量断言，遇到未知历史记录时会失败并回滚。

`0008_shared_subject_categories.sql` 将分类纠正为独立的 12 类通用字典，使用映射表分别为 TMUA 和 STEP 开放有效分类，并允许面试课暂不选择分类；同时把历史“考试信息”和“备考须知”拆分回填。

`0009_the_plan.sql` 最初引入年度总周期规划并补充面试课可用分类。旧面试课内容允许继续保持空分类，新建和编辑时由服务端要求选择有效分类。

`0010_rebuild_the_plan_matrix.sql` 处理旧版 `0009` 已经进入开发库、但尚无规划业务数据的情况，将课程树和逐月规则重建为年度说明、分区规划行、多时间块、行级文档链接与不可变版本快照。迁移在删除旧表前断言旧规划表全部为空；发现业务数据会主动中止，必须另行制定转换方案。

`0011_normalize_plan_taxonomy.sql` 新增面试课专属“面试准备须知”分类，纠正 2026 年截图导入数据的规划行名称和面试分类，并为所有受影响规划行生成新的完整版本快照。迁移在移除面试课旧“备考须知”映射前检查内容版本，发现已分类内容会主动中止。

`0012_derive_annual_plan_summary.sql` 增加细致规划行的推广周期汇总标记，并按原始规划表初始化推广行。被初始化的规划行生成新版本；页面据此从启用的细致规划自动推导发帖周期和推广周期。

`0013_reset_annual_plan_to_v0.sql` 将正式运营修改前的 THE PLAN 初始化过程折叠为 V0：每条规划只保留执行迁移时的当前完整快照，删除此前搭建和初始录入产生的其他规划历史，并让之后首次实际修改进入 V1。该迁移不修改内容发布排期的帖子版本。

`0014_remove_legacy_annual_summaries.sql` 清理已经由页面自动汇总替代的 2026 年旧总规划。迁移只接受“没有旧记录”的全新数据库，或名称和关联状态完全符合预期的七条初始化记录；遇到部分数据、额外通用规划或有效业务关联时会中止并回滚。
